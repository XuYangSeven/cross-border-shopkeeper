# 跨境掌柜 · Cross-border Shopkeeper

> 把一个跨境电商运营岗位拆成 **46 个可玩关卡**的微信小程序 —— 不联网也能学完，登录后进度跨设备同步。

## 这是什么

「跨境掌柜」是一个**岗位模拟学习工具**：你扮演一名新入职的跨境电商运营，从「第一天上班」开始，依次经历选品、上架、广告投放、物流库存、客服售后、数据复盘、资金经营八个阶段，最后独立经营一家店铺并应对每周的结算与决策。

它不是知识卡片，也不是选择题题库。每一关都要求你**做出一个会改变店铺结果的决定**：选哪个品、定价多少、广告预算怎么分、这周备多少货。决定错了不会挨骂，但营业数据会变差 —— 学习发生在「看到后果」的那一刻。

**技术定位**：原生微信小程序，**单机优先**。所有学习进度存在本机，不登录即可完整游玩；登录后额外获得跨设备同步。云服务是**加在上面的一层**，任何云端故障都只能降级为「这次没同步」，不影响闯关、结算、金币与星级。

## 它解决什么问题

跨境电商岗位培训长期靠「师傅带 + 看文档」，问题是：文档看了记不住，师傅没空盯全程，而新人真正犯错（比如广告预算全压在低转化词上、旺季备货不足）成本很高。

这个项目的假设是：**先在一个没有真实损失的沙盘里把坑踩完**。为此做了三件事：

| 设计 | 为什么这么做 |
|---|---|
| **决策型关卡**：多数步骤不给选项，要求输入数值或组合条件 | 选择题只能验证「认不认得」，输入与推演才能验证「会不会算」 |
| **推演与结算同源**：预测结果与周结算走同一套模型与取整规则 | 否则学生会发现「我按提示算的结果和结算对不上」，信任立刻崩塌 |
| **金币 + 星级双激励**：记录与「有没有做出有效决策」有关 | 星级不能重试，逼你认真；金币可以重试，允许你探索 |

## 教学体系

共 **8 章 / 46 关 / 230 个步骤 / 44 种步骤类型**。

| 章 | 主题 | 关卡数 |
|---|---|---|
| 1 | 入职培训 | 3 |
| 2 | 选品实战 | 6 |
| 3 | 上架优化 | 5 |
| 4 | 广告投放 | 8 |
| 5 | 物流与库存 | 6 |
| 6 | 客服与售后 | 6 |
| 7 | 数据分析与运营复盘 | 6 |
| 8 | 资金与经营决策 | 6 |

每章以一场 Boss 关（综合决策）收尾。

## 功能特性

- **决策型关卡引擎** —— 44 种步骤类型：数值输入、多条件组合、排序、拖拽归类、复述题、迁移题等，均由同一套 `level.js` 校验管线调度。
- **店铺经营沙盘** —— 从第 2 章起解锁。经营自己的店铺，每周结算一次：订单、营收、毛利、库存、资金链，与关卡里学到的概念一一对应。共 10 个店铺子页面。
- **求助与学习经济** —— 三级提示定价（L1 思路免费 / L2 线索 30 金币 / L3 解析 80 金币）。提示由题目的权威答案**自动派生**，取不到权威答案时如实降级并标注，绝不编造。提示**不影响星级**，只消耗金币 —— 惩罚求助会把人推离学习。
- **能力评估** —— 从答题证据聚合出五个维度的能力画像，而不是简单统计正确率。
- **云端同步（可选）** —— 微信一键登录后，进度 / 金币 / 错题本 / 能力记录 / 学习游标 / 店铺状态跨设备同步。含冲突检测：本机与云端都有新进度时**不自动选边**，交给用户决定。
- **像素化视觉规范** —— 全站圆角为 0、投影为双层实色、按下态不用透明度；语义色分成「对错 / 涨跌 / 收支」三条互不借用的轴（涨跌轴遵循中国市场惯例：红涨绿跌）。

│   │   ├── cloud.local.example.js  # 本地云配置模板（复制为 cloud.local.js）
│   │   └── shop.js                 # 店铺沙盘模型参数
│   ├── engine/                     # 16 个纯逻辑模块（不碰 UI，可 node 直测）

### 引擎模块

| 模块 | 职责 |
|---|---|
| `state.js` | 本机存档：读写、快照自愈、迁移、金币账本、错题本、同步接缝 |
| `sync.js` | 云端：登录、拉取、上传、冲突判定、去抖推送（纯函数区可单测） |
| `learning.js` | 学习证据 → 能力画像 |
| `hints.js` | 三级提示的自动派生与降级 |
| `scoring.js` | 关卡评分与星级 |
| `shop.js` | 店铺周推演与结算（与 `shop-view.js` 共用同一模型） |
| `ads.js` `inventory.js` `customer.js` `finance.js` `profit.js` `analytics.js` | 各章的业务计算模型 |
| `tasks.js` | 店铺任务体系 |
| `audio.js` | 音效与偏好（偏好走独立存储键，不进存档、不上云） |
| `events.js` | 每日随机事件（**完整实现但当前未接入**，见「已知限制」） |

## 快速开始

### 前置

- [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）
- Node.js ≥ 18（仅用于跑测试与生成 npm 产物，小程序运行不依赖本地 Node）

### 跑起来

```bash
git clone https://github.com/XuYangSeven/cross-border-shopkeeper.git
cd cross-border-shopkeeper
```

1. 打开微信开发者工具 → **导入项目**，目录选仓库根目录（`kuajing-miniapp`）。
2. 在 `project.config.json` 里把 `appid` 换成**你自己的小程序 appid**（当前是开发者的演示值，你无法用它上传）。
3. 菜单 **工具 → 构建 npm**（`miniprogram/package.json` 已声明依赖，产物落在 `miniprogram/miniprogram_npm/`）。
   - 不想装开发者工具也可以：`node tools/build-miniprogram-npm.js` 会做等价的事（含产物自检）。
4. 编译运行。**不需要云服务也能完整游玩**。

### 可选：启用云同步

复制配置模板并填入你自己的云服务配置：

```bash
cp miniprogram/config/cloud.local.example.js miniprogram/config/cloud.local.js
# 编辑 cloud.local.js，填入 applicationId / publishableKey
```

`cloud.local.js` 已被 `.gitignore` 忽略。**不创建它也能正常运行** —— 此时应用保持纯单机模式，「我的」页会说明当前是本机保存。数据库表结构与首次联调排查顺序见 [`docs/云服务接入说明.md`](./docs/云服务接入说明.md)。

## 关于开发方式

这个项目是 **AI 辅助开发（vibe coding）** 的产物：需求讨论、方案设计、编码、评审、文档都由人与 AI 协作完成，AI 承担了绝大部分实现工作。

因此项目把重心放在了**如何让 AI 的产出可被信任**上：

- **单一来源**：版本号只有一个来源（`config/constants.js`），章节名只有一个来源，提示定价只有一个来源，并由测试锁定，防止多份副本各自漂移。
- **可执行的验收标准**：不靠"看起来对了"，而是靠 748 条断言 + 6 个自研闸门把契约固化下来。
- **与 AI 协作时的检查清单**：开工前先确认「改这个文件会不会撞上并行改动」；验收时先问「这个数字是从哪读出来的」；修 bug 时先复现再改。踩过的坑记在 [`docs/`](./docs) 里。
- **明确写下已知限制**，而不是把没验证的东西说成已验证（见下）。

## 已知限制

诚实地说清边界，比含糊过去有用：

- **教学有效性尚未做真人验证**。工程可用性与内容完整性已验证（748 条断言、全量结构审计），但「学生用它能学会吗」这个问题，`docs/phase6/玩测记录表_第1轮.md` 里仍是空白，真人可用性复测没做。
- **真机验收未完成**。音频播放、触觉反馈、真机手势这三类无法在自动化测试里覆盖。
- **云同步只做过逻辑层验证**，未在真机上跑完整的「登录 → 换会话 → 真实读写」链路。
- **`engine/events.js` 每日随机事件完整实现但全站零调用**。接入会打破「推演与结算同源」契约并需要重标定任务可达性，属产品级改动，暂缓。
- **`pages/level/level.js` 是一个 1300+ 行的上帝文件**。已用「零新增 setData + 纯 CSS 动效」绕开性能问题，但结构问题未解决；拆分前需要先修改一条把它固定在同一文件里的测试断言。
