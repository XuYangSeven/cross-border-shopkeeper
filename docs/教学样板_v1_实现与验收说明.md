# 教学样板 · 实现与验收说明

> 版本：v0.6.0-hints ｜ 范围：第 1~8 章全部 46 关 + 店铺经营沙盘 + 新手引导页 + 求助与学习经济
> 第一轮：第 1~2 章打造教学闭环样板；第二轮：稳定性与体验加固；第三轮：把同一套机制铺到 3~8 章；第四轮：店铺升级为经营决策沙盘；第五轮：新增新手引导页；第六轮：全量优化评审（存档加固 / Tab 图标 / 字号可读性）；第七轮：求助与学习经济（三级提示 + 零提示奖励 + 金币账本）
> 目标：把「通关即结束」升级为「决策 → 反馈 → 复盘 → 迁移 → 能力评估」的可验证教学闭环

## 1. 教学闭环：现在每关跑完会发生什么

```
情境目标（关卡 goal + objectives 展示在顶部）
→ 知识卡（card）
→ 独立操作（quiz / calc / skuFilter / profitCalc / radarScore …）
→ 即时反馈（你的选择 / 正确答案 / 错因，不再自动跳转）
→ 错误重试（保留作答，扣效率分，不阻断学习）
→ 迁移题（transfer：换数据、换情境，3 题答对 2 题达标）
→ 结构化复述（reflection：结论 / 依据 / 风险 三段，至少覆盖 2 段）
→ 关卡结果（游戏星级 + 学习结果五维条 + 能力分）
→ 能力证据落库（可累计、可查看）
→ 去店铺应用 / 错题复盘
```

### 关键机制

| 机制 | 规则 | 代码位置 |
|---|---|---|
| 迁移题达标 | 3 题答对 2 题（≥66%），答错给出正确答案与解析 | `engine/learning.js#evaluateTransfer` |
| 复盘达标 | 三段中至少覆盖 2 段要点，未覆盖给出参考表述 | `engine/learning.js#evaluateReflection` |
| 能力维度得分 | 知识 25% + 迁移 35% + 复盘 25% + 效率 15% | `engine/learning.js#WEIGHTS` |
| 合规硬门槛 | 出现合规错误时该维度**封顶 60**，不能被其他分数抵消 | `engine/learning.js#COMPLIANCE_CAP` |
| 掌握度分档 | ≥85 熟练 / ≥70 掌握 / ≥60 基本达标 / 其余待加强 | `engine/learning.js#masteryOf` |
| 未达标不写进度 | 得分 <60 不写通关记录，不会解锁下一关 | `pages/level/level.js#finish` |
| 失败续学点 | 失败后把续学点落在迁移/复盘段，重进回到薄弱环节 | `pages/level/level.js#finish` |
| 错题自动归档 | 答错的选择题、迁移题与复述题进入错题本，按题目去重，上限 100 条 | `pages/review/review.*`、`engine/state.js#addMistakes` |
| 金币防刷 | 首次通关发全额；重复通关仅在星数提升时补差额 | `engine/state.js#clearLevel` |
| 提交去重 | 本步已判定完成或 350ms 内连点，重复提交一律忽略 | `pages/level/level.js#guardSubmit` |
| 结算幂等 | `finish()` 只执行一次，重复回调不会重复写证据或重复跳转 | `pages/level/level.js#finish` |
| 结算明细传递 | 学习结果走临时存档 `kuajing_result_payload`，URL 只带短参数 | `pages/level/level.js#finish`、`pages/result/result.js` |

### 本轮修正的既有缺陷

| 缺陷 | 影响 | 处理 |
|---|---|---|
| 2-3 陷阱文案写「60×30cm、体积重 0.6kg、大标准件 $4.13」 | 与商品库 `90×40×2cm` 不符，实际体积重 1.2kg、超大件1 $5.08、毛利率 15.2% | 文案改为与引擎实算一致 |
| 2-4 选项写「慢食碗 3.55 分 / 猫抓板 3.7 分」 | 与加权引擎实算 3.6 / 3.8 不符 | 已校正 |
| 1-2 迁移题答案 288 / 576 | 实为 2880 / 5760（1500×6%×32） | 已校正，并由测试断言锁死 |
| 选择题答后 1.4 秒自动跳转 | 学生来不及看解析，且误以为提交失败 | 改为展示「你的选择 / 正确答案 / 错因」后手动继续 |
| 失败也写通关进度 | 未达标也能解锁下一关 | 未达标不写进度，并把续学点落在迁移段 |
| 重复通关重复发金币 | 可刷金币 | 仅首次全额，星数提升补差额 |
| `onNegativePick/onNegativeSubmit` 与模板绑定名不一致 | 命名与行为不符，易误判为功能失效 | 统一命名为否定词语义，删除重复实现 |
| `onPickRx` 内两处 `127.0.0.1:7778` 调试请求 | 真机噪声 | 已移除，并由审计测试拦截回归 |
| 存档缺少版本与嵌套兜底 | 旧存档缺新字段会读到 `undefined` | 增加 `SAVE_VERSION` + `migrate()` |

cd kuajing-miniapp
npm test                 # 全量 17 个测试文件

### 3.2 微信开发者工具人工走查

建议先「清缓存 → 清除全部缓存 → 编译」，然后按下面顺序验收：

1. **进度可见**：进入 1-2，页面顶部应显示关卡目标、当前阶段标签（情境/知识/练习/迁移/复盘/Boss）、第 N/M 步与进度条。
2. **选择题反馈**：答对或答错后停在本步，显示「你的选择 / 正确答案 / 错因」，点「继续 ▶」才前进；答错时退出重进「我的」页可见错题数 +1。
3. **退出续学**：在 1-2 中途返回，地图顶部出现「继续上次学习」；进入后提示「已从上次的第 N 步继续」。
4. **迁移题**：1-2 迁移题填 2880 与 5760（第 3 题选 A）应达标；故意填错应显示逐题「你的答案 / 正确答案 / 解析」，且不通过。
5. **结构化复述**：三段都填「不知道」应不达标并给出参考表述；按示例改写后应达标，每段旁出现「要点达标（命中：…）」。
6. **关卡结果**：达标后结果页显示五维学习结果条、本关能力分、累计能力分、补强建议与下一步；按钮含「查看错题复盘 / 复习知识卡片 / 去店铺应用 / 返回地图」。
7. **未达标不推进**：在 1-3 故意让多数交互失分，直到总分 <60，返回地图应确认 1-3 仍未通关（无星）、2-2 仍锁定。
8. **能力累计**：「我的」页能力评估面板应出现「经营基础 / 选品」维度与分数；完成 2-6 后选品维度次数增加。
9. **错题复盘**：从结果页或「我的」进入错题页，按关卡分组显示你的答案、正确答案、错因，可「再练一次这一关」，可清除。
10. **Console 检查**：不应出现任何 `127.0.0.1:7778` 请求、模板表达式报错或 `setData` 路径告警。
11. **连点不重复加分**：在任意计算题快速双击「提交」，本关结果页的「目标完成度」不应超过 100%；在最后一屏快速双击「完成本关」只应跳转一次。
12. **初筛失败态**：2-2 故意把候选判成淘汰，提交后应就地显示每张卡的「判定有误 / 正确应选」与理由，并出现「再做一次」；重做后判定应清空。
13. **复述错题入本**：1-3 复述三段都填「随便写」，提交后进入错题页应看到类型为「结构化复述」的记录；再次提交同一段内容，错题条数不应增加。
14. **下一关 CTA**：通关 1-1 后结果页主按钮应为「进入下一关：1-2 …」，锁定关卡不会出现该按钮。
15. **第 3~8 章迁移题可用**：用「我的」页能力面板确认章节解锁后，任选 4-1、5-4、7-2、8-3 各跑一遍——它们的迁移题数值答案分别是 `5% / 8% / 20%`、`182 / 47`、`4 / 4 / 30`、`48.2 / 954`，填入应达标；填错应显示逐题解析且不通过。
16. **Boss 关教学闸门**：进入任一 Boss 关（如 6-6、7-6、8-6），在迁移题或复述题故意不达标时，「继续」按钮应**不出现**，只能「重新作答 / 修改后再提交」；达标后才出现「迁移达标，继续 ▶」「完成本关 ▶」。
17. **能力维度分章聚合**：「我的」页能力面板应随第 3~8 章推进依次出现 `Listing / 广告 / 供应链与库存 / 客服与经营 / 数据分析 / 资金决策` 六个维度，每个维度的分数只由对应章节的关卡贡献。
18. **知识卡片全章可用**：进入技能手册页，应看到 8 个分组（入职培训→资金与经营决策，按数字序排列），共 54 张卡；每张卡的「面试官会这样问」翻面可看；未收集的卡应显示为未拥有。进入任一第 4~8 章关卡（如 4-4、6-4、8-4），流程第一步应为情境对话、第二步为知识卡片，点「收下卡片」后才进入交互题。

## 4. 教学设计的验收口径（建议用于 20 人可用性测试）

| 指标 | 采集方式 | 建议阈值 |
|---|---|---|
| 首关完成率 | 完成 1-1 人数 / 启动人数 | ≥35% |
| 第 2 章完成率 | 完成 2-6 人数 / 启动人数 | ≥18% |
| 迁移题达标率 | 首次提交 `evaluateTransfer.passed` | ≥70% |
| 复述达标率 | 首次提交 `evaluateReflection.passed` | ≥70% |
| 错题复盘使用率 | 进入错题页人数 / 完成关卡人数 | ≥25% |
| 平均重试次数 | `retries` 均值 | ≤2 |
| 能力维度覆盖 | 有 ≥3 次证据的维度数 | ≥2 |

数据来源：`state.getAbility()`（能力证据）、`state.getMistakes()`（错题）、`state.getLearningProgress()`（续学）、`state.get().progress`（通关与星数）。

## 5. 20 人教学有效性验证方案（运营验收版）

### 5.1 样本与执行

| 项目 | 执行标准 |
|---|---|
| 招募结构 | 零基础转行者 8 人、在校生 4 人、有电商经验 4 人、培训/招聘从业者 4 人；排除项目组成员及熟悉策划案者 |
| 测试批次 | 第 1 批 10 人观察式测试（录屏+口述思考，不提示答案）；修复 P0/P1 后第 2 批 10 人回归测试 |
| 时间点 | D0 完成 1-1~1-3、2-1~2-2（45~60 分钟）；D3 完成 2-3/Boss 与迁移测评；D7 做延迟后测 |
| 测前采集 | 平台经验、数学基础、求职目标、5 道术语题+1 道利润计算题；说明“不评价个人能力”并取得知情同意 |
| 核心任务 | 3 分钟内找到下一步；完成模块认知、销售额公式、店铺诊断、商品筛选、利润核算、红线识别；每关结束不看卡片完成“目标—证据—风险”复述 |
| 观察记录 | 首次点击/输入、停顿>10 秒、误触、知识卡查看、求助、失败后的修正、是否引用数据；测后 1~5 分评价清晰度/真实感/负担/继续意愿 |

P0 问题定义为至少 3/20 用户遇到且阻断继续的问题；每 10 人一轮输出问题清单，记录用户数、严重度、复现步骤、责任人与修复版本。小样本仅用于方向判断，不作统计显著性结论。

### 5.2 埋点事件字典（MVP）

所有事件必须包含：`event_id`、匿名 `user_id`、`session_id`、`timestamp`、`app_version`、`channel`、`device`、`chapter_id`、`level_id`、`step_index`、`attempt_no`。不得上传姓名、手机号、简历原文或自由文本。

| 事件 | 必填业务字段 | 用途 |
|---|---|---|
| `acquisition_landing_view` | channel、referrer | 渠道到达 |
| `trial_start` | entry、time_to_start_ms | 激活 |
| `level_start` | level_id、resume_flag | 开始/续学 |
| `step_view` | step_type、card_id/question_id | 步骤曝光 |
| `step_answer` | step_type、item_id、answer_id、is_first_attempt、is_correct、response_ms | 首答与耗时 |
| `calc_submit` | formula_type、input_value、expected_value、is_correct、attempt_no | 计算掌握 |
| `diagnosis_submit` | selected_count、correct_count、false_positive_count、false_negative_count | 诊断质量 |
| `knowledge_card_view/collect` | card_id、source_step、dwell_ms | 知识使用 |
| `level_fail/complete` | score、stars、retry_count、duration_sec、first_pass_flag | 关卡漏斗 |
| `boss_complete` | objective_pass、compliance_pass、transfer_required_pass | Boss硬门槛 |
| `migration_submit` | base_item_id、variant_id、answer_correct、reason_coverage_goal/evidence/risk、attempt_no | 迁移能力 |
| `recall_submit` | prompt_type、coverage_count（0~3）、score、rubric_version | 结构化复述；仅传标签 |
| `error_review_open/replay_complete` | error_type、delay_days、correct_after_replay | 错题复习 |
| `report_preview/export` | dimensions_complete、export_success | 学习成果 |
| `retention_checkin` | day_n、review_task_done | D1/D3/D7 留存 |

首版可采用本地队列+批量上报；即使暂未接云端，也须按该字典记录结构化事件，保证后续替换传输层不改口径。事件需支持重复、乱序识别，建议以 `event_id` 去重。

| 复述达标率 | 目标/证据/风险至少覆盖 2 项且分数≥70 / 完成复述用户 | ≥50% |
| D3 延迟保持率 | D3 迁移正确率 / D0 迁移正确率 | ≥50% |
| D7 有效学习留存 | D7 再完成一项学习动作 / D0 启动用户 | ≥20% |
| “知道为何错” | 复盘后能选择正确错因 / 看过复盘用户 | ≥70% |
| 重复错误率 | 同技能第二次仍错 / 有二次作答用户 | ≤30% |
| 错题复盘使用率 | 进入错题页 / 完成关卡用户 | ≥25% |
| 报告预览率 | 预览报告 / 第 2 章 Boss 完成用户 | ≥40% |
| 关键埋点完整率 | 字段齐全有效事件 / 应采集事件 | ≥95% |
| 崩溃/空白率 | 崩溃或空白会话 / 测试会话 | <2% |

完成率、留存率和掌握率必须按用户分层（零基础/有经验）及渠道展示；不得用总时长、星数或好评替代掌握证据。

## 6. 第 3 章扩展验收门槛

### 6.1 P0 硬门槛（全部满足才允许扩章）

1. 无阻断级流程、存档、路由和解锁错误；至少 18/20 用户可独立找到下一步，关键数据不丢失。
2. 第 1 章完成率≥45%，第 2 章 Boss 完成率≥25%。
3. 第 2 章迁移首答≥60%、结构化复述达标≥50%、D3 保持率≥50%；至少 70% 用户能指出一票否决风险。
4. “知道为何错”≥70%，重复错误率≤30%；每个核心错题有解释、错因分类和复习入口。
5. 侵权、违规促销、平台红线等合规题错误时必须警示并阻止错误解锁；不允许用高分抵消合规错误。
6. 关键埋点完整率≥95%，能识别重复/乱序；崩溃或空白率<2%。

### 6.2 P1 质量门槛

- 中位单次学习时长 10~20 分钟；P90 不超过 35 分钟。
- 主观清晰度≥4/5，继续意愿≥3.5/5。
- D7 有效学习留存≥20%，报告预览率≥40%。
- 每个高频错误（用户数≥3）有明确修复动作；修复后回归批次不再出现同一 P0。

### 6.3 商业门槛（学习门槛达成后再测）

- 付费墙到达率≥25%、章节支付转化 5%~10%、退款率<5%。
- 商业指标不得掩盖学习质量问题；若 P0/P1 未达标，继续扩章或投放均暂停。

### 6.4 验收会议输出

每轮输出：一页漏斗（渠道→启动→完成→迁移→复述→D7）、一页错题热力图（技能×错误类型）、5 条用户原声及问题清单。最终结论仅三类：**继续扩第 3 章**、**带条件扩章（列明必须修复项）**、**暂停扩章并回炉第 1~2 章**。

## 7. 稳定性与体验加固（第二轮）

> 目标：把「能跑通」升级为「不会因为误触、退出、异常参数而算错分或丢数据」。

### 7.1 结算与流程稳定性

| 问题 | 影响 | 处理 |
|---|---|---|
| `next()` 无流转锁 | 快速连点会让 `stepIndex` 竞态，跳步或重复渲染 | 增加 `_transitioning` 锁 |
| `finish()` 无幂等锁 | 重复回调会重复写能力证据、重复跳转 | 增加 `finishing` 锁，重复调用直接返回 |
| 32 个提交入口无去重 | 连点会重复 `objDone++`，目标完成度被虚高 | 统一 `guardSubmit()`：本步已判定完成或 350ms 内连点一律忽略；换步与「再做一次」清零去抖 |
| 初筛失败自动放行 | 第 2 章初筛没过也照样进下一步，教学门槛失效 | 失败改为就地给出每张卡的正确判定与理由 + 「再做一次」，不再自动跳步 |
| 模块点亮 / 公式拼装成功后自动跳转 | 学生来不及看结果 | 改为显式「继续 ▶」按钮 |
| 复述失败不记录错题 | 复述是薄弱项却不进复盘本 | 复述未覆盖的字段按 `reflection` 题型写入错题，带缺失要点 |
| 迁移/复述重复提交重复记错题 | 错题本被同一题刷满 | `state.addMistakes` 按 `关卡+步骤+题型+题目+用户答案` 去重 |
| 续学只存 `stepIndex` | 中断后结算按后半段统计，星级与能力分失真 | 续学存档补齐 `quizTotal/quizCorrect/objTotal/objDone/retries/collectedCards/transferRate/reflectionRate` |

### 7.2 存档健壮性

- `state.js` 存档版本升到 **3**，新增 `meta / learningCursors / attempts / evidenceRecords / learningEvents / outbox / reportSnapshots`，为后续云同步预留。
- `migrate()` 改为**深拷贝 + 递归补默认值**：旧存档缺少 `shopState` 嵌套字段时不再读到 `undefined`，也不会与 `DEFAULT` 共享引用。
- `reset()` 改深拷贝，重置后不再与上一轮存档共享数组引用。
- `progress` 排除数组、`learning.stepIndex/stepTotal` 做非负整数边界校验。
- `collectCard()` 显式 `load()`，避免未初始化时 `cache` 为空。

## 9. 店铺经营沙盘（第四轮，v0.5.0-shop）

前八轮都在打磨「关卡内的教学闭环」，店铺 Tab 一直是占位功能。第四轮把店铺升级为**带约束的经营决策沙盘**——学生用有限的行动点和现金做取舍，看到可解释的因果反馈，跑完一周后被五维评分与六项任务同时检验。完整的设计规格（经营公式、参数表、操作目录、评分口径、验证清单）见 [《店铺模块 · 设计规格与实现说明》](./店铺模块_设计规格与实现说明.md)。

### 9.1 修掉的缺陷

| 级别 | 问题 | 处理 |
|---|---|---|
| P0 | `service_quality` 任务永不可达成（全站无法修改店铺评分） | 新增 `svc_ticket` / `svc_recover` / `svc_training`，评分与解决率都可被操作改变 |
| P0 | `ad_efficiency` 可白送（不投广告 ACOS=0 直接达标） | 新增 `acos_healthy` 方向：必须 `adSpend > 0` 且 `paidOrders ≥ 5` 才计入 |
| P0 | 店铺不是决策，只是「点按钮涨数字」 | 引入 12 行动点预算 + 16 项带代价/上限/前置条件的操作目录 |
| P1 | 推演与结算口径漂移（推演 33.3% / 结算 37.7%） | `deriveKpis` 改为按日取整再成周，模拟器复用推演的自然流量与转化率 |
| P1 | COGS 硬编码 `orders × 2.21`，与现金口径打架 | 统一为「净利 = 销售额 − 货品成本 − 广告费」，COGS 取模拟累计值 |
| P1 | KPI 与决策脱节（静态种子数据） | KPI 改为 `deriveKpis(当前决策)` 实时推演 |
| P1 | 任务与章节知识、能力维度无关联 | 每项任务补齐 `chapter` / `cardId` / `advice` / `targetPage` |
| P1 | 重复锁定同一周可重复发奖励 | 修正 `rewardClaimed` 作用域 |
| P2 | 六页 JS/WXML 是压缩占位、WXSS 全空 | 9 个店铺页面全部重写为真实决策界面，补齐独立 WXSS 与禁用态 |

### 9.2 关键设计

- **推演与结算同源**：无断货时推演与结算完全一致（orders 133 = 133）；默认决策 91→70 的差额是断货丢单 21 单，是教学信号而非口径漂移。
- **参数标定**：默认决策 2/6 达成、决策分 49「待改进」→ 完整解（12 点用尽）6/6 达成、决策分 88「优秀」。唯一弱项商品力 65 分是「12 点预算必须取舍」的设计意图。
- **结算回写教学闭环**：结算生成能力证据（`shop-week-N`）写进「我的 → 能力评估」，并追加 `shop_week_settled` 学习事件；触发红线时该维度封顶 60。

## 10. 新手引导页（第五轮）

前四轮的入口都是「冷启动直接进关卡地图」——新用户打开只看到一列关卡，不知道这个 App 是干什么的、能练出什么。第五轮补一个启动引导页作为第一屏。

### 10.1 做法

新增 `pages/intro/intro` 四件套，并把它注册到 `app.json` 的 `pages` **首位**，成为冷启动的第一屏。

页面自上而下五段：

| 区块 | 内容 |
|---|---|
| 品牌区 | 「跨境掌柜」+ 副标题 + 一句定位（在「星帆跨境」入职，从新人练到能独立操盘） |
| 你将扮演 | 一句话说明身份与目标：接手宠物用品店「PawPal」，用真实决策练判断力 |
| 这个 App 有什么 | 四项功能卡（关卡闯关 / 店铺经营沙盘 / 知识手册 / 能力评估），各带规模数字 |
| 一关是怎么练的 | 五步学习闭环：知道概念 → 动手决策 → 即时反馈 → 复盘表达 → 能力评估 |
| 开始 | 主按钮 + 免责小字（公司与人物均为虚构） |

### 10.2 两个关键细节

- **跳转必须用 `switchTab`**：目标「关卡地图」是 tabBar 页，用 `navigateTo` 会失败。结构审计的路由检查同时兜住了这条（未注册页面会被拦下）。
- **规模数字不写死**：关卡数来自 `config/levels/index` 注册表、卡片数来自 `config/cards`、能力维度数来自 `engine/learning.DIMENSIONS`，全部实时读取。这样以后加章节、加卡片，引导页文案自动跟着变，不会过期。测试里专门断言了这一点。

### 10.3 体验细节

- **CTA 文案随进度切换**：无进度显示「开始体验」，已通关任意一关则显示「继续学习」，并在下方补一行「已通关 X / 46 关 · 累计 ★ N」。
- **只读存档**：引导页只读 `state.get().progress` 用于渲染，不写任何状态。
- **样式沿用全站像素风**：深蓝 `#1A2B4A` / 金 `#D4A934` / 米 `#F2E8D5`，与关卡地图、店铺模块完全一致；长文本统一 `overflow-wrap: anywhere` 防溢出。

### 10.4 新增测试与结果

`tests/intro-page.test.js`（4 组断言）：

1. 页面导出 `onLoad / onShow / onStart`，首屏 4 项功能 + 5 步闭环齐备；
2. 点「开始」必须 `switchTab('/pages/map/map')`；
3. 展示的关卡数 / 卡片数 / 维度数必须与真实配置一致（防止写死过期）；
4. 有进度时文案切换为「继续学习」且正确统计已通关数与星数。

```bash
npm test   # 23 个测试文件
```

当前结果：**23 / 23 通过，0 失败**；结构审计自动识别为 `16 个页面 / 16 个模板 / 46 个关卡 / 4 个 Tab 图标`。
