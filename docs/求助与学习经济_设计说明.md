# 求助与学习经济 · 设计说明

> 版本：v0.6.0-hints ｜ 目标：把「金币只有产出没有消耗」补成一套有教学意图的闭环
> 前置：`docs/教学样板_v1_实现与验收说明.md`（教学闭环）、`docs/店铺模块_设计规格与实现说明.md`（店铺沙盘）
> 本文所有数字均来自实跑，不是估算；复现命令见第 9 节。

---

## 1. 起点：审计发现的问题

前一版审计（`docs/优化评审_第一轮.md`）里有一条 P1：

| 现象 | 证据 |
| --- | --- |
| **金币有产出无消耗** | `config/constants.js` 定义了 `HINT_COST: 50`，`engine/state.js` 导出了 `spendCoins()`，两者在 `miniprogram/` 下**零调用** |

顺着这条线又发现三个连带问题：

1. **`scoring.js` 早就预留了接口却没用上**。它的 `efficiency` 参数注释原文是「如提示使用次数、修改次数折算」——说明提示系统当初被设计过，只是没做。
2. **学生卡关时没有任何出路**。答错了只能一遍遍重试，没有「给个台阶」的机制。这是学习类产品最大的流失点。
3. **「金币」在「我的」页当核心数值展示，却无处可花**。整个激励闭环是塌的。

**「有产出无消耗」只是症状，真正的病是「学习行为没有被记账」。**

---

## 2. 设计判断

补一个消耗出口有很多种做法（商店、皮肤、抽卡）。我选了**求助**，理由是它同时解决教学问题和游戏问题：

| 判断 | 说明 |
| --- | --- |
| **求助本身就是教学内容** | 真实工作里遇到不会的事，正确动作是**查资料、问人、看案例**——而不是干耗着。把「求助」做成一个需要权衡的动作，比做商店更贴岗位 |
| **代价应该落在「奖励」上，而不是「惩罚」上** | 用提示不扣分、不影响星级，只是拿不到「零提示奖励」。求助是好的学习行为，不该被罚；但它也不该同时拿挑战奖励 |
| **第一级必须免费** | 提示系统的首要目的是降低「卡关即流失」。若第一级就收费，舍不得花金币的学生会继续卡着，反而放大了流失 |
| **不能只是「花钱买答案」** | 那样学生学到的是「有钱就能跳过」。所以设三级递进：思路（框架）→ 线索（台阶）→ 解析（答案） |
| **提示不能手写** | 项目有 230 个步骤、43 种类型。手写提示既写不完，也会在关卡内容改动后悄悄过期 |

## 3. 三级求助

| 级别 | 名称 | 价格 | 内容 | 教学含义 |
| --- | --- | --- | --- | --- |
| L1 | 思路 | **免费** | 「这题问『…』——先看清题目问的是哪个变量」 | 给框架，不给方向 |
| L2 | 线索 | 30 | 题目自带的公式提示 / 复盘提示；没有时给「考点定位 + 复习指引」 | 给台阶，不给答案 |
| L3 | 解析 | 80 | 正确答案与完整过程 | 直接给答案 |

**三条使用规则：**

1. **用了任何一级（含免费的 L1）就失去本关「零提示奖励」，并中断连胜。** 这是 L1「免费」的真实代价，必须在购买前就让学生看见——所以求助坞上常驻一行说明，而不是买完才提示。
2. **买高级会连带解锁低级**。低级内容更少，没有理由让直接买解析的人反而看不到思路。
3. **已解锁的档位不重复扣费**。重复点击是误触，不是消费意愿。

## 4. 内容从哪来：自动生成

这是本设计最关键的技术前提。项目里的可判定步骤**本身就自带答案与解析字段**：

| 字段 | 出现在 |
| --- | --- |
| `options[].correct` / `options[].explain` | quiz、transportChoice、launchStrategy、adPlacement |
| `blanks[].hint` / `blanks[].answer` | calc、adMetricCalc、freightCalc |
| `questions[].answer` / `questions[].explain` | transfer（迁移题，16 个） |
| `fields[].answer` | reorderCalc、serviceMetrics、funnelCalc、cashFlowCalc、financeCalc、financeBoss |
| `reviewPrompt` | 第 7~8 章大量计算与决策题 |
| `items[].prescriptions[].good` / `items[].options[].valid` | diagnose、diagnoseChoice、reviewBoss、riskChoice |
| `fields[].sample` | reflection（复述题给参考表述） |

所以 `engine/hints.js` 的做法是**从这些字段派生**，而不是另写一套。改了题干，提示跟着变。

**提取方式刻意不写死嵌套路径**：用一个递归扫描找出所有被标记为 `correct` / `valid` / `good` 的条目，避免新增题型时漏掉、也避免猜错字段名。

### 4.1 实测覆盖

```
可求助步骤：105 / 230
其余 125 个是 dialog(55) / card(69) / profitDemo(1) —— 阅读与示范类，本就没有「对错」，
给它们「提示」只会让人误以为自己读错了，因此不提供求助。

三级内容覆盖率：L1 105/105、L2 105/105、L3 105/105（无空壳）
L3 精确答案：64 / 105
```

### 4.2 「不编造」是硬约束

剩 41 个步骤的 L3 标记为 `exact: false`，分两种：

- **主观题**（reflection 15 个）：给参考表述，它本来就是范例而非唯一解。
- **无唯一答案**（skuFilter、profitCalc 等）：如实说明「这一关没有唯一标准答案，需要你自己推演。建议回看本关的知识卡片」，**而不是用通用话术伪装成答案**。

被移除的一种做法（实测踩出来的）——L2 曾把错误选项的 `explain` 拼成「常见误区」，两个问题：

1. **三选项题排除两个等于白送答案**，而 L2 只卖 30、L3 才卖 80；
2. **脱离选项上下文会被误读成在肯定错误选项**。例如「常见误区：影响非常大。不但没补贴，还可能影响绩效。」——读起来像是在夸它。

现在 L2 改为「考点定位 + 复习指引」（如「本关考的是『经营基础』，对应第 1 章『入职培训』。先回看这一章的知识卡片，再回到题目。」）。这条已写进 `tests/hints.test.js` 的回归断言：**L2 不得引用任何选项文本或错项解析**。

## 5. 产出的另一半：零提示奖励与连胜

| 机制 | 规则 | 意图 |
| --- | --- | --- |
| 零提示加成 | 整关未用任何提示 → 通关金币 ×1.5 | 让「自己啃下来」有可见回报 |
| 零提示连胜 | 连续第 N 关零提示通关额外 +5×min(N,3) | 制造「不想断」的心理张力 |

**断连胜的条件**：用任何一级提示、或通过失败重刷以外的方式中断。**未通关不算断**（失败不该惩罚学生）。

**防刷**：加成只在 `clearLevel` 真的产生 `base > 0` 时发放，即**只有首次通关或升星才给**。重刷已通关且未升星的关卡，既不奖励也不动连胜——否则可以靠反复刷简单关卡无限赚金币。

## 6. 参数怎么算出来的

参数不是拍的（全程 46 关、按三星 base 30 估算）：

| 项 | 计算 | 结果 |
| --- | --- | --- |
| base 总和 | 46 × 30 | 1380 |
| 零提示加成 | 1380 × 0.5 | 690 |
| 连胜加成 | 5×(1+2+3) + 5×3×43 | 675 |
| **收入上限** | | **2745** |
| 每关都用线索 | 46 × 30 | **1380 = base 总和** |

**关键设计点：把「每关都用线索提示」的支出定成恰好等于 base 总和。**

于是：

- 一路靠线索提示通关的人，刚好花光基础收益、攒不下钱 → 求助有真实分量；
- 想有余钱就得少用提示 → 产生取舍；
- 解析（80）相当于两三关的收益 → 明确是奢侈品。

同时因为 L1 永远免费，**「金币不够」不会变成「没法做题」**——最差情况也有一句思路可以看。

### 6.1 实跑验证

```
=== 五种玩法的经济结果（全三星通关 46 关）===
① 全程零提示              余额 2745 | 连胜 46 | 买到  0 | 想买但买不起  0
② 每 3 关买 1 次线索       余额 1605 | 连胜  0 | 买到 15 | 想买但买不起  1
③ 每关都买线索            余额   30 | 连胜  0 | 买到 45 | 想买但买不起  1
④ 每关都买解析            余额  100 | 连胜  0 | 买到 16 | 想买但买不起 30
⑤ 混合（约 1/4 关卡求助）   余额 1185 | 连胜  1 | 买到 38 | 想买但买不起  1
```

结论与设计意图一致：

- ③ 每关都买线索 → 余额 **30**，几乎精确花光，验证了「打平」的标定；
- ④ 每关都买解析 → 30 次被拦下，说明解析确实是奢侈品，学生必须**选择性使用**；
- ② 与 ⑤ 适度求助 → 仍有 1000+ 结余，不会让学生因为「怕花光」而不敢求助。

## 7. 与既有系统的衔接

| 约束 | 处理 |
| --- | --- |
| **不破坏关卡评分公式** | 未使用提示时，`efficiency = max(0, 1 − retries×0.1)` **完全不变**，所有既有星级断言不受影响。提示只影响金币，不影响星级 |
| **不新增步骤类型** | 求助坞挂在 `renderStep` 结尾的统一 `setData({ view })` 之前，**一处改动覆盖全部 43 种步骤类型**，不触碰 `structure-audit.test.js` 第 8 条把 `case 'x'` 固化在同文件里的契约 |
| **不破坏 `clearLevel` 契约** | 新增 `settleLevelReward` 在其之上叠加加成，`clearLevel` 的「首次全额 / 升星补差额」语义原样保留 |
| **引擎层保持纯函数** | `engine/hints.js` 不依赖 wx、不读写存储、不改入参、不用随机数（与 `learning.js` 同一约束） |
| **不出现第二份定价** | 价格只在 `constants.HINT_TIERS` 定义，测试断言 `hints.TIERS === CONSTANTS.HINT_TIERS` |
| **店铺成为金币的可再生来源** | 关卡金币是一次性的（46 关全通约 1380），店铺周任务（最高 110/周）可重复。两者构成「学关卡 → 经营赚币 → 换提示」的循环 |

### 7.1 顺手修掉的两个既有缺陷

1. **`spendCoins` 没有 `load()` 保护**。同文件的 `collectCard` / `saveLearningProgress` 都有，只有它没有；若在 `init` 之前调用会因 `cache` 为 `null` 抛异常。已修并加断言。
2. **`saveLearningProgress` 会丢字段**。它只取固定字段，新增的 `hintsUsed` / `hintsSpent` 若不落盘，学生退出重进就能**洗掉「用过提示」的记录、白拿零提示奖励**。已修，并在 `finish()` 失败分支与 `onUnload()` 两处都写入。

## 8. 界面

| 位置 | 内容 |
| --- | --- |
| **关卡页 · 求助坞** | 所有可判定步骤底部常驻。折叠态显示「💡 卡住了？」与当前状态（未用/已失效）；展开后三级列出，已解锁显示内容、未解锁显示价格，金币不足按钮变灰但仍可点（点了告诉你还差多少） |
| **结果页 · 金币结算** | 通关奖励 / 零提示加成 / 连胜奖励 / 合计四行，并根据本关是否用提示给出解释（「用了 2 次提示，所以不获得零提示加成」「全程没用提示，连胜已累计到 5 关」） |
| **我的页 · 金币** | 余额、零提示连胜、最近 6 条收支流水（来源标签 + 时间 + 带符号金额）。原来放在「我的档案」里的金币行已挪到这里，身份信息与经济信息分开 |

**配色轴说明**：账本收支用的是**第三条语义轴**（绿=进账、红=出账），与前两条区分——对错轴用 `app.wxss` 的 `.text-up/.text-down`，指标涨跌轴用 `styles/shop-page.wxss` 的 `.kpi-d`。三条轴含义不同，类名不得互相借用。

## 10. 已知边界

- **提示内容质量受题目数据质量约束**。若某道题的题干本身歧义，自动生成的思路会跟着不准。这是「不手写」的代价，换来的是一致性与可维护性。
- **L3 对 41 个步骤不含具体答案**（主观题与多轮 Boss）。这是刻意的诚实降级，不是遗漏。
- **连胜以「关」为单位**，不区分关卡难度。第 8 章的 Boss 关与第 1 章的入门关加成相同。若要按难度加权，需要给关卡增加难度字段。
- **未接入埋点**。目前「用了多少提示」只在本地存档里，无法做全局的难度标定。若后续发现某关的求助率异常高，说明该关的题目或提示需要复核。
- **「提示不影响星级」是刻意的**。若将来希望求助有更重的代价，应优先调价，而不是接回 `efficiency`——那样会变成对求助的惩罚，与第 2 节的设计判断冲突。
