## 2. 与像素风基线的差距分析

### 2.1 现状的视觉语法

像素风基线（`app.wxss` + `styles/shop-page.wxss`）实际由以下 CSS 语法构成：

| 语法要素 | 实现 | 风格含义 |
|---|---|---|
| 硬描边 | `border: 3~4rpx solid #1A2B4A` | 无抗锯齿的「描线」质感 |
| 硬投影 | `box-shadow: 6rpx 6rpx 0 rgba(26,43,74,.25)` | 偏移实心块，像素风标志性语汇 |
| 平面填色 | 无渐变、无圆角高光 | 色块化 |
| 按压位移 | `:active { transform: translate(2rpx,2rpx) }` | 机械式反馈 |
| 色板 | 深蓝 `#1A2B4A` / 金 `#D4A934` / 米 `#F2E8D5` / 面板白 `#FFFDF7` | 高对比三色系 |

### 2.2 需要点破的「风格纯度」现实

这套语言是 **「像素风 UI 外壳」而非「真像素画」**，有两处客观偏离，必须让用户知情：

1. **圆角而非直角**：`.panel` / `.btn-primary` 用 `border-radius: 8rpx`，进度条 / 标签用 `999rpx` 胶囊。严格像素风是零圆角。当前圆角在 750 逻辑宽度下仅约 4px，观感接近硬边，但**不是纯像素**。
2. **系统字体而非像素字体**：`font-family: -apple-system, "PingFang SC", ...`。正文是标准无衬线，**文字层完全没有像素化**。

### 2.3 判断：WXSS-only 长期够不够用？

**够用，且对本项目是更优解，不建议改换为位图主导。** 理由：

1. **产品形态决定**：这是**信息密集型学习工具**（46 关 / 9 个店铺子页 / KPI 条 / 决策评分条 / 金币账本 / 长文本解析）。位图主导的像素 UI 在**文字清晰度、缩放适配、信息密度**上全面劣于 CSS。
2. **体积安全**：当前主包 788 KB。一旦引入背景 / 立绘 / 纹理位图，很容易吃掉全部 1.24 MB 余量，直接威胁 2 MB 硬上限（微信主包超限即无法上传）。
3. **可维护性**：CSS 可被单人维护、可热改、可随配色变量批量调整；位图需要设计产出与重导，本项目无专职设计资源。
4. **一致性已被守住**：全站同一套类名基线（`.panel` / `.btn-primary` / `shop-page.wxss` 共享），视觉身份统一，未见偏离美术圣经的实现。
5. **平台适配**：CSS 随设备 DPR 与字号缩放自适应；位图在小程序里受 `image` 默认尺寸与 DPR 影响，易模糊或留白。

**唯一需要用户拍板的取舍**（非缺陷，是风格上限）：若追求「真像素」质感，代价是**像素字体**（需中文字库子集化，增包体、降长文可读性）。当前判断：**Phase 7 前不做**（见 §5）。

## 3. 玩测前必须补的资产

### 结论：**0 项。玩测前无需新增任何图片资产。**

理由（敢下判断）：

1. **玩测要验证的是「教学有效性」，不是视觉**。当前玩测目标为「第 1 章有无死点 / 迁移通过率 / 单关耗时 vs 声明值」（见《工作室阶段诊断_第一轮》§5.2）。视觉资产对此零贡献。
2. **当前视觉一致性已达标**。WXSS 基线足以支撑玩测观感，不会因「画面太素」而干扰对「教学节奏」的判断。
3. **补位图会污染反馈**。玩测期间新增位图 = 引入加载失败 / 体积波动 / 机型渲染差异三个新变量，反而让「卡顿 / 白屏」类反馈无法归因到设计本身。
4. **违背稳定基线原则**。玩测版本已冻结在 `a12579a`，视觉层保持不动有利于对比与回滚。

> 即：**玩测期美术动作 = 冻结，不动。** 若玩测反馈出现「不知道点哪里 / 图标看不懂」类问题，届时按具体命中点单开小修，而非提前囤资产。

## 4. Phase 7 上架必须补的资产清单（按优先级）

> 平台约束前情：微信小程序**主包 2 MB 上限**；上架素材**一律不进主包**，放仓库根目录 `assets-launch/`（在 `miniprogramRoot` 之外，天然不打包）；分享图建议走 CDN 外链。

| 优先级 | 资产 | 数量 | 建议尺寸 | 格式 | 用途 / 为什么必须 | 落位 |
|---|---|---|---|---|---|---|
| **P1** | 小程序图标（头像） | 1 | **144×144** | PNG（≤500 KB，硬限 2 MB） | mp 后台「小程序信息」**提审硬门槛**；发现页 / 搜索 / 历史列表入口 | `assets-launch/app-icon-144.png` |
| **P1** | 上架截图 | **5** | **750×1334** | PNG / JPG（≤2 MB/张） | mp 后台**提审硬门槛**；决定商店转化 | `assets-launch/store-screenshot-01..05.png` |
| **P2** | 分享卡片封面 | 1 | **500×400（5:4）** | JPG（≤128 KB，超限被强制压缩） | Phase 7 明确要接 `onShareAppMessage` / `onShareTimeline`；会话 / 朋友圈分享卡片主图 | CDN 外链优先，或 `assets-launch/share-card-5x4.jpg` |

**合计：3 类 / 7 个文件。**

要点：
- **图标**：微信会自动裁成圆角（半径≈边长 22%），**核心图形须居中且不贴边（安全边距 ≥11%）**；小尺寸（列表内可能 <80px）下必须一眼可辨，避免堆细节、避免纯文字。建议直接复用现有像素语汇（「店铺」棚身 / 「关卡」旗标）提炼单一符号。
- **截图**：5 张建议叙事顺序 = ① 品牌页（intro hero） → ② 关卡地图 → ③ 一关决策卡（体现「边玩边学」） → ④ 店铺经营看板（KPI/决策条） → ⑤ 能力评估 / 复盘。前 2 张是转化关键。
- **分享封面**：`imageUrl` **5:4**，内容居中、四周留 10% 安全边距（微信会智能裁切）。因 ≤128 KB，用 JPG 质量 80–85 + 二次压缩。

> 规格复核提示：以上像素值为 2026-09 微信通行要求，提审前建议以 mp 后台**当时的**校验提示为准（平台会变）。

## 5. 明确「可以不做」的清单及理由

> 目的：一次性关闭这些议题，避免后续反复讨论。

| # | 不做项 | 理由（判断，非可能性罗列） |
|---|---|---|
| N1 | **主包内的一切像素位图**：关卡背景、角色立绘、道具图标、装饰纹理 | **最重要的一项「不做」。** 与「信息密集型学习工具」的第一性目标冲突：位图带来 2 MB 主包压力、缩放模糊、无主题适配、单人维护成本；而 WXSS 已把视觉一致性做到位。做它 = 用成本换更低可用性。 |
| N2 | 像素字体（Zpix / 丁卯点阵体等） | 中文字库子集化后仍显著增包体，且点阵字体严重降低长文（解析 / 复盘）可读性，与学习工具的「读得清」冲突。当前系统字体清晰且零成本。**若用户坚持要更强像素感，单列为可选增强，不列入上架必需。** |
| N3 | 重绘 / 精细化现有 Tab 图标 | 8 个图标已达 81×81（微信推荐值），NEAREST 硬边符合像素风，辨识度经 `tools/tabbar-preview.png` 目视校对，无改的必要。 |
| N4 | 关卡 / 店铺的插图式引导图 | 引导已由文字 + 决策卡 + 提示系统（105 步）承担，插图不解决任何已验证的问题，只增成本。 |
| N5 | Loading / 骨架屏位图 | 用 CSS 可实现（同款硬边块 + 描边），无需位图。 |
| N6 | 自定义启动图（Splash） | **技术上不可做**：小程序启动图由微信平台统一控制，开发者无法自定义。常被误列为需求，此处明确排除。 |
| N7 | 广告 / 营销 Banner | 项目无商业化投放场景，上架期无需求。 |

## 6. 规格建议

### 6.1 色板（沿用现有，禁止私自扩色）

| 令牌 | Hex | 用途 |
|---|---|---|
| 主色·深蓝 | `#1A2B4A` | 描边 / 正文 / 导航栏底 / 页脚 |
| 强调·金 | `#D4A934` | 主按钮 / 选中态 / 星级 / 进度填充 |
| 底色·米 | `#F2E8D5` | 页面背景 / 次级文字（深底上） |
| 面板白 | `#FFFDF7` | `.panel` 背景 |
| 次蓝 | `#2E4A7A` | 次按钮 / 次级强调 |
| 未选中灰 | `#9E9E9E` | Tab 未选中（与 `app.json` 对齐） |
| 危险红 | `#A84A42` / 描边 `#7A2E2A` | 危险操作 |
| 语义·对错轴 | `#4CAF50` / `#E53935` / `#FB8C00` | 正确 / 错误 / 提醒（仅用于答题与合规判定） |
| 语义·涨跌轴 | `#C62828`（升）/ `#2E7D32`（降） | 仅用于指标涨跌（中国市场惯例） |

> 注意：项目存在**两条互不相同的语义色轴**（对错轴 vs 涨跌轴），资产制作时不得跨轴取色（详见 `app.wxss` 注释）。

### 6.2 命名规范

- 字母小写 + 中划线分隔，语义词序 `品类-用途[-态]`：
  - 上架素材：`app-icon-144.png`、`share-card-5x4.jpg`、`store-screenshot-01.png` … `store-screenshot-05.png`
  - 页内资产（若未来新增）：`ui-empty-<page>.png`、`bg-<scene>.png`（**当前无此类资产**）
- 上架素材统一落 **`assets-launch/`**（`miniprogramRoot` 外，不被打包）；分享图优先 CDN，命名带尺寸后缀。

### 6.3 格式与体积红线

| 场景 | 格式 | 尺寸 | 体积红线 |
|---|---|---|---|
| Tab 图标（现状） | PNG-24 透明底 | 81×81 | 忽略（实测 ≈0.26 KB/张） |
| 小程序图标 | PNG（透明或实底） | 144×144 | ≤500 KB（硬限 2 MB） |
| 上架截图 | PNG / JPG | 750×1334 | ≤2 MB/张 |
| 分享封面 | JPG（质量 80–85） | 500×400（5:4） | **≤128 KB**（超限被微信强制压缩降质） |
| 任何进主包的图 | — | — | **单张 ≤200 KB，主包总量 ≤2 MB** |
