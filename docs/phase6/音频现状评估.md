## 2. 价值判定：音频对「边玩边学」的边际价值

游戏内关键反馈节点（答对/答错、迁移题、复述题、星级结算、周结算、金币收支）目前**信息都已通过 toast 文案与视觉状态传达完整**，音频能加的是**情绪强度**，加不了**信息量**。

- 对「学得对」的价值：**低**。学习闭环靠题目解析、复述三段、能力反馈——这些是阅读型任务，音频不改变「能否学会」。
- 对「玩得爽」的价值：**中**。答对/答错的瞬时音效、结算星级音效是休闲游戏里最有效的正反馈放大器，能降低重复刷题的疲劳感。
- 但本项目的产品定性是**岗位模拟学习工具**（目标「边玩边学」），不是以爽感驱动的休闲游戏。**音频提升的是留存与情绪，不是学习效果。**

一句话：**音频是「锦上添花」，不是「地基」。**

## 3. 若要做：极简方案（供后续阶段参考，本轮不执行）

按性价比排序，只做「反馈音效」一层，不做背景音乐（BGM 成本最高、收益最分散）。

| 优先级 | 节点 | 建议音效 | 成本 | 实现方式 |
|--------|------|----------|------|----------|
| P0 | 答对 | 短促上扬提示音（≤0.3s） | 1 个音效文件 | 判定回调内 `InnerAudioContext.play()` |
| P0 | 答错 | 低沉短音（≤0.3s） | 1 个音效文件 | 同上 |
| P1 | 关卡结算星级 | 1–3 星递进音效（可 1 个文件 + 音量/音高变体） | 1–3 个文件 | result 页 `onLoad` 触发 |
| P2 | 金币收支 | 收币/扣币音 | 2 个文件 | 结算时触发 |
| — | 周结算 / 迁移 / 复述 | 复用答对/答错音即可 | 0 | 不单独做 |

### 微信小程序必须写进方案的三条现实约束

1. **主包体积 2MB 上限**：当前 `miniprogram/` 源码 788K（含 images 32K），源头上传会经压缩，但音频是**已压缩的二进制**、压缩率极低，会**近乎 1:1 吃主包体积**。几个 wav 就能顶掉大半预算。
2. **自动播放限制**：`InnerAudioContext` 无法自动播放，**首次播放必须发生在用户交互（tap）回调的调用栈内**，否则静默失败（不报错、不出声）。意味着任何「进页面自动响」的设想都不成立。
3. **音频资产走 CDN 或分包**：小程序不支持热更新，音频应放**分包**（`subPackages`）或**远程 CDN + `wx.getFileSystemManager` 缓存**，主包只留极少量短音效。注意：**纯单机、无后端**是当前硬约束——若走 CDN 就等于引入网络依赖，需与主理人/程基岩确认是否破线；走分包则需改造 `app.json` 页面结构。

**额外性能预算**：同发音频实例建议 ≤2（一个反馈音 + 一个环境音），`InnerAudioContext` 实例需池化复用，避免频繁创建导致内存抖动。

## 4. 明确结论

> **本轮（Phase 6 玩测）不做音频。**

理由（一句话立场）：

1. **不阻塞玩测目标**：玩测要验证的是稳定性与学习路径，音频是新增变量，只会干扰结论归因。
2. **成本 > 收益**：把音频做对（资产 + 分包/CDN + 首次交互解锁 + 池化）的成本，明显高于本轮它带来的边际收益。
3. **信息已完整**：现有 toast + 星级视觉已把所有判定信息传达完整，音频只能加情绪、不能补信息。
4. **引入网络/结构风险的时机不对**：走 CDN 会破「纯单机」约束，走分包要动 `app.json` 结构——都不该在玩测前做。

### 什么条件下需要重新评估

- 玩测反馈中「节奏平淡 / 答对缺乏正反馈 / 刷题疲劳」成为**高频结论**；
- 项目从「学习工具」向「留存/商业化打磨」推进（如做章节氛围音乐、品牌主题音）；
- 上架评审或运营方明确要求听觉体验；
- 主包体积预算出现明确余量，且决定接受分包改造或 CDN 依赖。

## 5. 防呆提示：未来接音频最容易踩的坑

**最大的坑：`InnerAudioContext` 的自动播放限制 + 复用陷阱。**

- **静默失败**：首次播放若不在用户 tap 回调内，代码不报错但没声音，极难排查 → 所有音效必须挂在明确的点击事件上。
- **实例互抢**：一个 `InnerAudioContext` 播新音会打断上一个；多个音效共用需正确 `play/stop` 或按事件建池，否则出现「音效缺失/被截断」。
- **手机静音键/静音模式**：系统静音下音频通道失效，本地开发用模拟器测不出 → 必须准备「静音开关」UI 与无声降级路径，并**真机验证**。
- **混淆音频与触觉**：本项目连 `vibrateShort`（振动）都还没接；若只想加轻反馈，**触觉比音频成本低一个数量级**（仅需首次交互后调用、无体积负担），可作为音频的先行替代方案。
