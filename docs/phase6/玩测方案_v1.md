## 1. 玩测目标与非目标

### 1.1 第 1 轮验证什么（目标）

| # | 验证命题 | 判定载体 |
|---|---|---|
| G1 | 教学闭环**流程可通**：情境→知识卡→独立操作→即时反馈→错误重试→迁移→复述→结果页，能一路走到底 | 6 关是否都抵达结果页 |
| G2 | **卡点可定位**：学生第一次撞墙发生在哪个步骤、是哪一类步骤 | 「首次答错位置」观察项 |
| G3 | **求助链路可用**：三级提示在真实卡住时能取到、价格能被感知、免费档能救急 | 「提示使用」观察项 |
| G4 | **迁移与复述两段能跑**：换数据后能否复用同一标准、能否用自己的话重组结论 | 「迁移题」「复述题」观察项 |
| G5 | **结果页反馈可读**：星级 / 五维学习结果 / 能力分 / 弱项与下一步，学生看得懂 | 「星级与得分」观察项 |
| G6 | **无工程级污染**：本轮不出现白屏/崩溃/卡死干扰反馈归因 | 「崩溃/白屏」补充观察项 |

### 1.2 第 1 轮**不**验证什么（非目标）

| # | 明确排除 | 原因 |
|---|---|---|
| N1 | **难度曲线是否合理** | 执行者是设计者本人，已知答案，难度感知必然失真（见 §7） |
| N2 | 教学有效性（「学到没有」） | 单样本 + 已知答案，无法构成学习效果证据；需第 2 轮起非设计者样本 |
| N3 | 留存 / 放弃率 / 付费意愿 | 样本量=1，且非真实用户 |
| N4 | 经济平衡（金币够不够花） | 已由 `tools/simulate-coin-economy.js` 模拟；真人验证留到第 2 轮起 |
| N5 | 第 3~8 章内容 | 本轮范围只到 2-3；后续章节另开轮次 |
| N6 | 店铺经营沙盘 | 与关卡教学闭环不同链路，本轮不覆盖 |
| N7 | 美术 / 音频表现 | 由 `art-director` / `audio-director` 独立评估，不在本条链路 |

## 2. 轮次规划

| 轮次 | 样本 | 样本画像 | 范围 | 本轮**唯一**目标 | 样本引入方式 |
|---|---|---|---|---|---|
| **第 1 轮** | 用户本人（1 人） | 24 岁跨境物流 B 端 PM；懂海运/空运/铁运/卡运/单证/清关；**无亚马逊运营实操、无店铺运营经验** | 1-1~1-3 + 2-1~2-3（6 关） | 验证**流程与卡点**，不判难度 | 本人即执行者 |
| 第 2 轮 | ≥1 名同岗位非作者 | 具备跨境基础、但**未读过本项目**、未参与设计 | 全第 1 章 + 全第 2 章（9 关） | 在「已知答案」偏差移除后，第 2 章是否仍能过 | 找同事/同行；口头只说「边玩边出声想」，**不透露答案与坑点** |
| 第 3 轮 | ≥1 名无跨境背景新人 | 目标用户**下限**（应届/非电商岗），验证零门槛 | 全第 1 章（3 关） | 第 1 章是否真「零基础可入」 | 社群/朋友招募；同样不出声提示 |
| 第 4 轮起 | 每轮 ≥2 样本 | 混合（1 名有基础 + 1 名无基础） | 逐章推进，每章抽 2~3 关键关 | 覆盖第 3~8 章的难度与配比 | 滚动招募；记录口径沿用本方案 |

**轮次推进门**：上一轮「通过标准」（§5）全绿方可进入下一轮；出现「回 Phase 2」（§6.1）则先修内容、再重跑同一轮次，不带病推进。

> 轮次规划满足《工作室阶段诊断》SOP 的「≥3 轮」要求；第 1 轮是流程探路轮，第 2 轮起才进入有效性验证。

## 4. 观察项定义

> 每项三问必答：**怎么记 / 记成什么格式 / 为什么记**。所有记录填进 `玩测记录表_第1轮.md`。
> 记录时「步骤序号」一律用 §3 的序号；不可求助的步骤（dialog/card）不产生答错，无需记。

### 4.1 核心 8 项

| # | 观察项 | 怎么记 | 记成什么格式 | 为什么记 |
|---|---|---|---|---|
| O1 | **单关实测耗时 vs 声明 duration** | 进入关卡（出现「第 1 步 / 共 N 步」）时开表；到结果页停表。中途离开用同一表暂停、回来继续累计 | `mm:ss`，并写比值 `实测÷声明`（例 `11:20 / 8min = 1.42`） | 声明 duration 是对外承诺的节奏；偏离反映「设计者以为的时长」是否成立 |
| O2 | **首次答错出现在哪个步骤** | 第一次出现「你的选择 ≠ 正确答案」或「有偏差」的步骤，立即记下序号 | `步骤序号 + 步骤类型 + 该步在测什么`（例 `7:quiz 断货后果`） | 定位「学生第一次撞墙在哪」，判断知识卡是否给了足够前置 |
| O3 | **提示使用情况** | 每次点开提示记：级别 + 这是该步的第几次尝试 + 花费金币 | `步骤序号-L级-第几次尝试`（例 `6-L2-第2次`）；全程未用记 `none` | L1=没思路、L2=知道考什么但算不出、L3=完全不会；级别分布=卡点性质 |
| O4 | **迁移题结果** | 首次提交后逐子题对错，记答对数 | 首次 `答对 n/3`；若重试另起一行 `重试 m 次后 n/3`；无迁移关记 `N/A` | 迁移是「学会没有」的核心证据，比选择题更能区分记忆 vs 理解 |
| O5 | **复述题结果** | 提交后页面显示「要点覆盖 x/N」，照抄 x 与 N | `x/N`（**N=该关字段数：1-2→2，1-3→3**，不是固定 3）；无复述关记 `N/A` | 复述检验能否用自己的话重组「结论/依据/风险」，是表达层证据 |
| O6 | **星级与最终得分** | 结果页照抄四项：星级、总分、能力分、能力等级与弱项 | `★n \| total=xx \| ability=xx \| 等级=xx \| 弱项=xx` | 锁定星级门槛与权重是否与真实体感一致 |
| O7 | **即时吐槽（定性）** | 边玩边出声想；遇到「啊？/ 哦～ / 这啥」立刻记**原话** | `步骤序号 \| 原话`（口语化，**不润色、不改写**） | 数值看不到「困惑/顿悟」发生在哪一步；原话是后续改文案/改讲解的一手素材 |
| O8 | **是否中途查阅站外资料** | 只要切出小程序去查东西就记 | `Y/N + 步骤序号 + 查了什么 + 为什么查` | 若查的是**知识卡本应覆盖**的内容 → 知识卡没讲清，回 Phase 2 |

### 4.2 补充 3 项

| # | 观察项 | 怎么记 | 记成什么格式 | 为什么记 |
|---|---|---|---|---|
| O9 | **崩溃 / 降级弹窗 / 卡死** | 出现即记。**① 降级弹窗**（「页面加载失败」+「返回首页」）→ 记弹窗标明的页面名，并抄 Console 的 `[pageGuard] xxx.onShow 失败` 堆栈；**② 真·白屏**（无内容、无弹窗）→ 记 `真崩溃`；**③ 卡死/无响应** → 记卡住的秒数 | `Y/N + 步骤序号 + 类型(降级弹窗/真崩溃/卡死) + 页面名 + 堆栈(如有) + 是否可恢复` | 页面已加错误边界（P6-T1）：降级弹窗可直接定位到具体页面 onLoad/onShow，把「工程问题」与「设计问题」分开；仍白屏基本可判真崩溃 |
| O10 | **金币余额与提示花费** | 每关结算后记当前金币、本关提示花费、是否拿到零提示加成 | `coins=xx \| 本关花费=xx \| 加成=Y/N` | 第 1 关金币=0，可验证「免费档救急」假设与加成是否被正确发放 |
| O11 | **知识卡停留时长（配比探测）** | 记每个 `card` 步骤的停留秒数（快速划过 <2s 标记 `划过`） | `步骤序号:停留秒数/划过` | 呼应诊断 R6：若读卡被大量划过，说明「游戏 70%/学习 30%」配比可能失衡 |

> **性能基线（供判断「卡」是设计还是环境，来自 P6-T1 剖析）**：主包 527.8KB / 2MB；全站 `setData` 静态调用 188 次，其中 `level.js` 独占 164 次（`renderStep` 单方法 37 次）。
> 若玩测中出现关卡页交互偶有卡顿，方向在 `level.js`，**不是环境问题**——记录时请注明「页面 + 操作 + 现象」，不要笼统写「卡」。

## 6. 失败 / 阻塞判定

### 6.1 回 Phase 2 重新设计（结构性返工，砍掉重做内容）

| 触发条件 | 为什么算结构问题 |
|---|---|
| 任一新关**死点**：>60s 无有效操作、且执行者明确说「不知道要做什么」，退出重进仍卡同一处 | 属步骤缺失/目标不清/知识卡未覆盖，改数值救不了 |
| 单关耗时 **> 声明×2.0** | 节奏假设整体崩，需拆分或重估步骤数 |
| **迁移题**：执行者（已知答案）仍首次答错 ≥2 子题，或首次提交不及格 | 迁移题标准/前置知识不足，不是难度问题 |
| **复述题**：按知识卡内容如实作答仍两关都全不达标 | 复述判定标准（keywords）与知识卡内容脱节，需重校卡文与判定 |
| **同型错误跨 ≥2 关**（如同一陷阱在两关造成同型答错） | 知识结构性问题，需补统一讲解 |
| O8 显示知识卡**应覆盖**的内容需要频繁查站外 | 知识卡没讲清，回 Phase 2 补卡 |

### 6.2 只需调数值 / 配置（不动结构）

| 触发条件 | 处置 |
|---|---|
| 单关耗时在 **1.5×~2.0×** 之间 | 改 `duration` 声明值，或删 1~2 个 `card`/`quiz` 步骤 |
| 星级体感与数值不符（普通表现拿不到 3★ / 差表现也能 3★） | 调 `SCORE_WEIGHTS` 或 `STAR_THRESHOLDS` |
| 复述题因 `minHits` 过严导致合理表述被判不达标 | 调该字段 `keywords` / `minHits`（属数值配置） |
| 提示金币不够用 / 加成感知不到 | 调 `HINT_TIERS` / `COIN_REWARD` / `NO_HINT_MULTIPLIER` |
| 迁移题 `passRatio` 与子题难度不匹配 | 调 `passRatio` |

> 全套数值均为**单一来源配置**（`config/constants.js`、各 `chapter*.js`），改一处即生效，无需动 `level.js`。

### 6.3 数据作废 / 重跑

| 情况 | 处置 |
|---|---|
| 出现崩溃/白屏 | 该关数据**作废**，修 bug 后重跑该关 |
| 中途离开 >5 分钟且分不清计时 | 分段计时并标注「分段」，仍可用，但耗时不作为 P4 判据 |

## 7. 样本偏差声明

1. **偏差来源**：第 1 轮执行者 = 设计者本人，**已知全部答案与坑点**（如 2-3 的体积重陷阱、1-2 的坑题）。
2. **由此第 1 轮的结论**仅限：**流程可执行性、卡点位置、UI/文案歧义、崩溃与性能**。
3. **第 1 轮不得用于**：判定难度曲线、留存量、教学有效性（学到程度）、经济平衡——这四项一律留到第 2 轮起非设计者样本。
4. **为何仍要做第 1 轮**：设计者本人能最快暴露「流程断点、按钮无响应、步骤丢内容、结果页缺行」这类**与难度无关**的问题，成本最低、前置价值最高。
5. **第 2 轮起的偏差控制**：不透露答案与坑点、要求出声想（think-aloud）、不中途提示、同岗位非作者 + 无基础对照组各取样本。

## 8. 首轮执行指引（在微信开发者工具里怎么开始、玩到哪停、怎么交回）

### 8.1 环境准备
1. 打开**微信开发者工具** → 「导入项目」→ 目录选**仓库根**：`/Users/soren/Desktop/Soren工作文档/跨境项目/kuajing-miniapp`（`project.config.json` 已指定 `miniprogramRoot = miniprogram/`，不要选到 `miniprogram` 子目录）。
2. 点「编译」，若面板无红字报错即就绪；启动页为 `pages/intro/intro`。
3. **清零存档（关键）**：进「我的」Tab → 「重置存档」（确认）→ 保证 `金币=0`、`进度=空`、`错题=空`。这一步是为了让第 1 关真实处于「新玩家、零金币」状态。
4. 设备二选一，**全程不改**：模拟器（输入填空体验一致）或真机预览（扫码，手感更真实）。若用真机，把记录表放在另一台设备/纸上。

### 8.2 开玩步骤
1. 走进「关卡」Tab → 点 **1-1 第一天上班**。
2. 看到「第 1 步 / 共 N 步」时**开计时**；到**结果页**时**停表**并记录。
3. 全程**出声想**（建议手机开录音，省去手写打断）。遇到困惑/恍然大悟的原话直接说，回头转写进表。
4. 每关结束后，先在记录表的**逐关汇总表**填一行，再进下一关。
5. 顺序固定：**1-1 → 1-2 → 1-3 → 2-1 → 2-2 → 2-3**（关卡按前一关通关解锁，顺玩即可）。

### 8.3 边玩边记的口径
- 「答错」= 页面出现「你的选择 ≠ 正确答案」或「有偏差/未达标」；quiz 不能重试，选错即记错并继续。
- 「提示」只统计**主动点开并解锁**的那一级；没点开不算。
- 「卡住」= 从该步出现到产生有效操作的秒数；`≤60s` 才算无死点。
- 缺失组件（该关无迁移/无复述）统一记 `N/A`，**不要写 0**。

### 8.4 玩到哪停
- **完成 2-3「利润核算」并看到结果页后即停止。**
- 不要继续 2-4（本轮范围外）。
- 若某关出现**降级弹窗**（「页面加载失败」+「返回首页」）：记弹窗页面名 + Console 的 `[pageGuard] xxx.onShow 失败` 堆栈 → 点「返回首页」回到 intro → 从地图重新进入该关（自动续学）→ 继续；该关标注「含降级弹窗」。
- 若出现**真·白屏**（无内容、无弹窗）或**卡死**：记录发生步骤与屏幕状态 → 退出重进 → 继续；该关标注「含崩溃」，该关数据按 §6.3 作废重跑。

### 8.5 记录怎么交回
1. 填写 `docs/phase6/玩测记录表_第1轮.md`（可直接在该文件填，或另存 `玩测记录表_第1轮_已填.md`）。
