## 2. 逐项「改前 → 改后 → 理由」

### 2.1 直角硬边（本轮第一号改动）

| | 改前 | 改后 |
|---|---|---|
| `.panel` | `border-radius: 8rpx` | `border-radius: 0` |
| `.btn-primary/secondary/danger` | `border-radius: 8rpx` | `border-radius: 0` |
| 进度条 / 标签 / 徽章（`shop-page.wxss`） | `border-radius: 999rpx`（药丸） | `border-radius: 0`（方块） |
| 全局兜底 | 无 | `button { border-radius: 0 }`（抹掉微信 `<button>` 自带 5px 圆角） |

**理由**：像素风的底层语汇是**直角硬边**——一个像素要么在格子里要么不在，没有「半格圆弧」。圆角是它的反义。8rpx 在当前 750 逻辑宽度下虽只约 4px、观感接近硬边，但它让整套 UI 停留在「圆角卡片版」，是**风格纯度**上的硬伤，也是主理人实测点名的第一号问题。

### 2.2 双层不透明硬阴影

| | 改前 | 改后 |
|---|---|---|
| `.panel` | `box-shadow: 6rpx 6rpx 0 rgba(26,43,74,0.25)` | `box-shadow: 8rpx 8rpx 0 #0E1830, inset 4rpx 4rpx 0 #FFFFFF` |
| `.btn-primary` | `box-shadow: 4rpx 4rpx 0 #1A2B4A`（单层） | `box-shadow: 6rpx 6rpx 0 #0E1830, inset 4rpx 4rpx 0 #EBCB6B` |
| `.btn-secondary` | 无投影 | 同款双层（内高光 `#4A6DA3`） |
| `.btn-danger` | 无投影 | 同款双层（内高光 `#C56A60`） |

**理由**：半透明阴影 `rgba(...,0.25)` 在浅底上会渲染出一圈**抗锯齿灰阶**——这恰好是像素风要消灭的东西。改为**不透明**深色实体块（`#0E1830`，比描边更深一档）制造厚度，再叠一层 `inset` 白色/亮色高光表示左上受光面。「外深 + 内亮」两层实色，就是像素 UI 表达厚度的标准做法。

### 2.3 按钮三态（默认 / `:active` 按下位移 / `[disabled]`）

**改前**：`.btn-primary` 有 `:active`（位移 2rpx、投影 4→2rpx）；`.btn-secondary`/`.btn-danger` **无** `:active`；三者 `[disabled]` 一律 `opacity: 0.5`。

**改后**：

- 三个按钮统一 `:active` 机制：**面下移 4rpx，投影由 6rpx 收到 2rpx** —— 外沿不动、面下沉，读起来就是「被按进底座」的机械式反馈（非缓动）。
- `[disabled]` 不再用半透明：改为硬灰实色 `bg #CFC9BC / text #3D3A34 / border #8A857A / 无投影`。

**理由**：① 三态不统一是像素 UI 的破绽（次级/危险按钮点了没反馈）；② `opacity` 会把**文字**一起变淡，禁用态对比度随之掉到不可读；硬灰实色可精确控制对比度（实测 `#3D3A34` on `#CFC9BC` = **6.87:1**，通过）。

### 2.4 面板标题条（新增）

新增 `.panel-title`：通栏深蓝条 `bg #1A2B4A / text #F2E8D5 / 底部 4rpx 深色压边`，用 `margin: -24rpx -24rpx 20rpx` 抵消 `.panel` 内边距，贴在面板顶端形成「窗口标题栏」。

**理由**：改前全站面板都是「一块白底 + 描边」，缺少**层次与锚点**；标题条给了面板一个视觉起点，也让「这是什么模块」一眼可辨（信息密集型工具的分区效率直接提升）。

### 2.5 像素分隔线（新增）

新增 `.px-divider`（4rpx 实线）/ `--dash`（虚线）/ `--soft`（浅色）/ `--pixel`（硬停靠渐变画的**方块虚线**，可选）。

**理由**：改前分隔靠各页自己写 `border-top: 2rpx solid #E5E5E5`，中性与不统一。收进全局后，分隔语义有统一出口；`--pixel` 用等宽色块画虚线，是「不用位图也能像像素」的范例。

### 2.6 徽章与星级（新增）

新增 `.px-badge`（+ `--gold/--navy/--danger`）、`.px-stars`（+ `.off` 空星）。

**理由**：改前只有 `.stars` 与各页零散的 `.badge`/`.tag`，没有统一的徽章体系。补齐后，「状态/等级/数量」有统一载具。

### 2.7 像素化进度条（新增 + 修复共享条）

- 新增 `.px-progress`（+ `--thin`）与 `.px-progress-fill`（+ `--navy/--ok/--bad`）。
- 同步改写共享条：`shop-page.wxss` 的 `.points-bar`/`.points-fill`、`.decision-bar`/`.decision-fill`。

**理由**：改前进度条是 `999rpx` 胶囊 + 纯色填充，读起来是「流体质感」。像素风的进度条应能读出「一格一格」——用 **硬停靠渐变**（`repeating-linear-gradient`，相邻色标等值 → 边缘无抗锯齿）把填充切成等宽色块，**不引入位图**即达成。

### 2.8 通用工具类（新增）

新增布局类（`.u-row/.u-col/.u-center/.u-between/.u-wrap/.u-grow/.u-shrink0/.u-min0/.u-wrap-text`）、文本类（`.u-bold/.u-dim/.u-muted/.u-right`）、间距类（`.u-mt-*/.u-mb-*/.u-gap-*`）、可见性（`.u-hidden`）、尺寸档（`.u-text-lg/.u-text-xl`）。

**理由**：为交互线（以及后续单人维护）提供**零成本复用件**，避免每页重写 `display:flex; align-items:center`。`.u-text-lg/xl` 同时是**文本缩放的挂载点**（见 §2.9）。

### 2.9 可访问性：形状冗余 + 对比度加固（登记项 R9）

**改前**：全站**无**色盲模式、**无**文本缩放；对错状态**只靠红绿**区分。

**改后（新增，供交互线挂用）**：

| 类 | 作用 |
|---|---|
| `.mark-ok` / `.mark-bad` / `.mark-warn` | 用 `::before` 注入 `✓ / ✗ / !`，**在颜色之外叠加形状冗余**，色盲用户可辨 |
| `.cb-ok`（蓝 `#1565C0`）/ `.cb-bad`（橙 `#9A5C00`） | **色盲安全替代配色**，与红绿轴一一对应，供「色盲模式」切换时替换 `.text-up/.text-down` |
| `.text-up-strong / -down-strong / -warn-strong` | 浅底正文用的**高对比度**变体（原 `.text-up` 在浅底仅 2.73:1） |
| `.u-text-lg / .u-text-xl` | 文本缩放档位挂载点 |

**用法约定**：`::before` 在 WXSS 的 `<text>` 组件上不被保证渲染 —— 形状冗余类请挂在 `<view>` 上；若交互线必须挂 `<text>`，请把 `✓/✗` **直接写进文案**。

**对比度实测（WCAG 2.1，`#FFFDF7` 面板底 / `#1A2B4A` 深底）**：

| 前景 | 背景 | 对比度 | 判定 |
|---|---|---|---|
| `#1A2B4A` 正文 | `#FFFDF7` | 13.87:1 | ✅ |
| `#D4A934` 金 | `#1A2B4A` 深蓝 | **6.40:1** | ✅（主理人要求实测的项，通过） |
| `#F2E8D5` 米 | `#1A2B4A` 深蓝 | 11.61:1 | ✅ |
| `#1F7A33`（up-strong） | `#FFFDF7` | 5.31:1 | ✅ |
| `#C62828`（down-strong） | `#FFFDF7` | 5.53:1 | ✅ |
| `#9A5C00`（warn-strong） | `#FFFDF7` | 5.29:1 | ✅ |
| `#6E6E6E`（新 `.sub`） | `#FFFDF7` | 5.01:1 | ✅（旧 `#777` 仅 4.40，**已修**） |
| `#3D3A34`（禁用态字） | `#CFC9BC` | 6.87:1 | ✅ |
| ⚠ `#4CAF50`（旧 `.text-up`） | `#FFFDF7` | **2.73:1** | ❌ 见下 |

> ⚠ **已知残留（不在本轮改动范围）**：旧 `.text-up(#4CAF50)` 在浅底只有 2.73:1。
> 它是**既有**类，被 `app.wxss` 注释、`美术资产审计.md §6.1` 等多处引用为「对错轴」权威色，改动它会连带多处文档口径失真。

## 5. 程序化像素资产：**本轮不做**

**结论：不加位图，也不创建 `tools/gen-pixel-assets.py`。**

理由（判断，非可能性罗列）：

1. **WXSS 已能覆盖全部需求**：直角、硬阴影、方块虚线、分段进度条、徽章——本轮的像素语汇**件件可用样式实现**，没有一项非位图不可。
2. **保护「0 位图引用」这条既有资产属性**：全站 `<image>` 0 处、`url()` 0 处。一旦引入位图，就必须新增 `background-image: url()` 或 `<image>` 组件，同时引入**加载失败 / 体积波动 / 机型渲染差异**三个新变量——这三者正是上一轮玩测纪律（美术冻结）要规避的。
3. **与信息密集型学习工具的第一性目标冲突**：本项目 46 关 / 9 个店铺子页 / KPI 条 / 决策条 / 金币账本 / 长文本解析，位图在**文字清晰度、缩放适配、信息密度**上全面劣于 CSS。
4. **不为零资产写脚本**：交付一个产出 0 文件的生成脚本 = 引入需要长期维护的死代码，与单人维护的项目现实相悖。**待真有位图需求时再建脚本，届时沿用 `gen-tabbar-icons.py` 的 27×27 ×3 NEAREST 手法。**

> 若未来（如 Phase 7 上架素材）确需位图：上架素材一律落仓库根 `assets-launch/`（`miniprogramRoot` 外，天然不打包），不污染主包。此结论沿用《美术资产审计》§4/§5。
