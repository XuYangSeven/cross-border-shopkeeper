# 音频优化：规格与实现（P6 玩测·UX 并行线 C）

> 版本 v0.6.0-hints ｜ 归属：音频（阮和鸣）｜ 定位：**情绪与节奏，不是信息载体**
> 一句话结论：1 条可循环 BGM + 6 个 chiptune 音效已生成并接线；音频总量 **377.1 KB**（上限 600 KB），`npm test` 22/22。
> ⚠ 播放行为只能在真机验证（本文 §6 给了验收清单）。本环境**未、也无法**实跑 `InnerAudioContext`，故不作「已实测播放成功」的声明。

---

## 1. 现状 → 方案

- 现状（改动前）：全站零音频 —— 无资产、无 API 调用。瞬时反馈只有 `wx.showToast` + 星级/状态视觉。
- 用户决策：明确要求加音乐。因此本轮立项。
- 声音语言：与像素风同源，只用 **8-bit 芯片语汇**（方波/脉冲波、三角波、白噪声），不用现代 synth pad / 混响铺底 / 环境音。
- 定位约束（沿用上一轮论证）：音频只加**情绪强度**，不承担判定信息。答对/答错依旧由 toast 文案与视觉表达；音效即使听不见也不影响过关。
- 生成方式：纯 Python 手写 PCM（本机 `numpy` 不可用）→ `wave` 落 WAV → `ffmpeg`(libmp3lame) 编码 mp3。**确定性、一条命令重跑**（噪声固定种子，两次运行 md5 完全一致）。

## 3. 接线点

| 位置 | 接线 | 说明 |
|---|---|---|
| `miniprogram/app.js` | `onLaunch → audio.init()` | 读偏好 + 预创建实例，**不播放**（自动播放会被拦） |
| `miniprogram/pages/me/me.wxml` | 根节点 `bindtap="onPageTap"` | 兜底手势入口：页内任一点击幂等 `startBgm()` |
| `miniprogram/pages/me/*` | 两个 `<switch>` → `setPref` + Toast | 开关状态 `onShow` 由 `getPref()` 回填 |
| **待交互线（UX-B）接线** | 引导页「开始」、答题 correct/wrong、结算 settle、金币 coin、解锁 unlock、通用 tap | 调用点必须落在**各页 tap 回调内**，见 §4.1 |

> 为什么手势触发不能写在 `app.js`：小程序**没有**全局触摸监听 API（无 `wx.onTouchStart`；`onAppRoute` 在导航后异步触发，不在手势同步栈内）。`play()` 必须在 `bindtap` 的同步调用栈里执行。因此本项目把「首次交互」挂在 **`audio.sfx()`**（其调用点皆在 tap 内，顺带启动 BGM）与「我的」页根节点兜底点击上。
> **需主理人确认的一项**：引导页（`pages/intro/`）首个手势（「开始体验」按钮）不在音频线可写范围内。建议 UX-B 在此按钮上接 `audio.sfx('tap')`（即自动启动 BGM），或批准音频线加 2 行 `bindtap="onFirstTouch" → audio.startBgm()`。

> **已接线但需注意手势栈的两处（交互线在途）**：`result` 页结算音、`shop-settlement` 页结算音、`map` 页新解锁音，均在 `onLoad/onShow` 类**非手势**回调里触发。进入这些页面之前用户必然已点击过（音频已解锁），多数平台允许「解锁后异步播放」，故通常能响；若真机无声，排查方向是把该音挪到进入该页的那次点击上贴身触发，或接受静默（不得影响页面展示）。已就此同步 ux-lead。

## 4. 三条防呆措施的具体实现

### 4.1 首次交互前静默失败 —— 怎么避免
- BGM **不在** `onLaunch/onShow` 自动播；启动只发生在手势调用栈内：① 任意控件点击的 `audio.sfx()` 顺带启动；② 「我的」页 `onPageTap`；③ 用户打开「背景音乐」开关的 `setPref()`。
- `startBgm()` **幂等**：`bgmPlaying` 为真时直接返回，绝不把音乐重置回开头。
- **自动重试**：真实播放状态由 `onPlay/onPause/onStop/onEnded/onError` 回调跟踪。若 `play()` 被静默拦截（无报错、无 fail 回调），`bgmPlaying` 保持 `false`，**下一次手势会再试**，不需要用户重启。

### 4.2 单实例互抢 —— 怎么避免
- **BGM = 独立单例**（`bgm`），与音效完全分离，永不被音效打断。
- **音效 = 3 槽池轮转**（`sfxPool`，`sfxCursor` 取模）。不同音效落在不同槽 → 可重叠、互不打断；同一槽被连续触发才 `stop()` 后重播（同音效快速连击会截断上一次，可接受且符合直觉）。
- 同槽复用时不重复赋 `src`（`sfxPoolSrc` 记忆），减少本地重载延迟。
- **`destroy()` 时机**：本引擎是 **App 级单例**，不随页面销毁重建 → 不存在「页面切换后残影播放」；短音效自然结束。切后台只 `pause()` BGM（见 §4.3），不 destroy，避免回前台重新加载。

### 4.3 静音键导致「无报错无声」 —— 怎么应对
- iOS 物理静音拨片下音频通道失效，**任何小程序 API 都无法检测**，只能靠设计兜底：
  1. **可见开关 + Toast 反馈**：用户看到「音效已开启」，知道自己点过，而不是以为界面坏了。
  2. **开启即自检**：打开「音效」开关时立刻播一声 `tap.mp3`，用户当场就能判断声音通不通。
  3. **保留 `obeyMuteSwitch` 默认值（true）**，不越权绕过系统静音。
  4. 文档与真机清单明确「静音键下无声是系统行为，非缺陷」。
- **全部路径静默降级**：所有 `wx.*` 调用包 `try/catch`；`unavailable` 标志在「无 `wx` / 创建实例失败」时短路后续调用。任何情况下**不抛错、不弹 toast**，音频永远不会把页面搞崩。
- **偏好独立存储**：key `kuajing_audio_pref_v1`，不进 `state.js` 存档结构，避免与存档自愈逻辑耦合。

## 6. 必须由用户真机验证的清单

> 本环境无法实跑 `InnerAudioContext`。逐条「动作 → 期望 → 听不到先查什么」。**开发者工具与真机行为不一致，以真机为准。**

1. **首次交互启动 BGM**：冷启动进引导页 → 点「开始体验」→ 进入关卡地图。期望：地图页能听到循环 BGM。听不到先查：(a)「我的」两开关是否都开；(b) 引导页「开始」是否已按 §3 提示接入 `sfx('tap')`；(c) 手机是否静音键/媒体音量为 0。
2. **音效触发**：依次点按钮(tap)/答对(correct)/答错(wrong)/结算(settle)/金币(coin)/解锁(unlock)。期望各有对应声音。无声先查：交互线是否已在对应 tap 回调里调用 `audio.sfx('...')`。
3. **开关生效**：关「背景音乐」→ 音乐应立即停；再开 → 应立即响。异常先查 `onToggleBgm` 是否被调用、`switch` 的 `checked` 是否随 `getPref()` 变化。
4. **静音键**：iOS 拨到静音 → 期望无声（系统行为，非缺陷）；提示用户关静音键或调媒体音量。
5. **连续快速答对**：期望最多 3 条音效可重叠；同一音效极速连击时上一次被截断（可接受）。
6. **切后台/锁屏返回**：期望 BGM 暂停、回前台自动复播。未复播先查：iOS 是否拦截了非手势的 `play()` —— 此时**点任意控件**应能重新启动（`sfx` 会重试）。
7. **BGM 循环接缝**：连续听 ≥3 轮，听接缝是否有可感知停顿。mp3 编解码有起止填充，可能造成极小间隙；若明显，处理方向：延长循环（改 `BARS/BPM` 重生成）或接受。
8. **长时间与多次切页**：连听 10 分钟并来回切 tab。期望 BGM 只有一路（不叠加成双份）、无音效残影。若叠加 → 说明创建了重复实例，检查 `init()` 幂等与页面是否各自 new。
9. **响度**：BGM 应明显轻于音效、不抢注意力。偏响/偏轻 → 调脚本 `normalize(b, 0.50)` 后重生成。

## 7. 未做项与边界

- **未做战斗/Battle 音**：项目无战斗场景。若将来加，需独立 BGM 状态机 + 音量 ducking，而非复用学习底噪。
- **未做环境音**：无持续场景音需求；环境音会与「低频密度低、不抢注意力」的学习定位冲突。
- **未做分包/CDN**：为守「纯单机」约束，资产全部在包内；余量充足（占 45.8%），暂无分包必要。
- **未做音量分级/自定义**：只提供开关，不做滑杆。
- **未做 VO/语音**：项目无配音需求。
- **未接入具体事件点**：`correct/wrong/settle/coin/unlock` 的触发时机由交互线（UX-B）在页面 tap 回调内接线 —— 这是跨线依赖，见 §3 的「待交互线接线」。
- **待美术线（可选）**：开关控件目前用原生 `<switch>`；若希望像素风定制外观，需要全局/组件级样式支持（音频线未改 `app.wxss`，避免与美术线冲突）。
