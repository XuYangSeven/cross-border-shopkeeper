## 3. 真实缺陷修正（本轮的实质产出）

### 3.1 `level.js` 提示购买：连点二次扣费（P1，已修）

**问题**：`onBuyHint` 的重复保护只有 `if (!target || !target.ready || target.unlocked) return;`。
`target.unlocked` 来自 `hint.tiers`，是**上一次 setData 的快照**——两次快速点击可能都落在同一次 setData 生效之前，于是**两道都放行、金币被扣两次**。这是真实副作用而非纯展示问题。

**修法**（`level.js:406-441`）：加实例级重入锁，且**两条路径都必须解锁**：

```js
if (this._buyingHint) return;          // 进入前先查锁
...
this._buyingHint = true;               // 通过所有校验、即将扣费前才上锁
if (!state.spendCoins(...)) {
  this._buyingHint = false;            // 扣费失败路径解锁
  wx.showToast({ title: '扣费失败，请重试', icon: 'none' });
  return;
}
...
this._buyingHint = false;              // 成功路径解锁
this.coinFeedback();
```

**为什么不用现成的 `guardSubmit()`**：全站已有 `guardSubmit()`（`level.js:457`，被 **32 个**提交入口调用）。它拦的是**时间**——`_lastSubmitAt` 是**全站共享**的时间窗（`now - _lastSubmitAt < 350ms` 即拦），而不是「这一笔扣费是否已落账」：

- 若在 `onBuyHint` 里调 `guardSubmit()`，会与提交路径**互相污染**：买完提示 350ms 内提交答案会被误拦。
- 购买是**真实副作用**（扣金币），需要的是**操作级锁**——「同一笔操作只能扣一次」，与 350ms 能否过去无关。

因此只补 `_buyingHint` 实例锁，**不新增第二套通用机制**，避免两套保护互相打架。

### 3.2 `result.wxml` 星级：单文本节点无法逐个弹出（已修）

**问题**：改前 `{{starsText}}` 是**一个文本节点**（服务端拼好的 `★★☆`），CSS 无法对它内部的星做逐个动画。

**修法**：拆成 3 个独立节点，同时**保留 `starsText` 作为星级的单一来源**（供测试与降级）：

```xml
<view class="stars big mj-stars">
  <text wx:for="{{starSlots}}" wx:key="*this"
        class="mj-star {{index < stars ? 'on' : 'off'}}">{{index < stars ? '★' : '☆'}}</text>
</view>
```

```js
starSlots: [0, 1, 2],   // result.js 新增字段
```

> 刻意不删 `starsText`：它是既有测试断言的读取对象，也是 `mj-stars` 动画不可用时的降级文案。删掉会把「动效」变成星级文案的第二份真相。

### 3.3 `level.wxml:437` 迁移题：答错时错项无任何标记（已修）

**问题**：改前选项类表达式为

```xml
class="option {{q.picked === o.key ? 'picked' : ''}} {{q.result ? (q.result.correct && q.result.correctAnswer === o.key ? 'right' : '') : ''}}"
```

当 `q.result.correct === false`（用户答错）时，条件不成立，**没有任何选项拿到 `right` 或 `wrong`**。
后果：学生看到反馈框写「❌ 错误」，但**选项本身完全没有标记**——不知道错在哪一项，也无法与「正确答案」对照。这是判定反馈链的断点。

**修法**：补上错项分支，并同时挂形状冗余类：

```xml
{{q.result ? (q.result.correct && q.result.correctAnswer === o.key ? 'right mark-ok'
             : (q.picked === o.key && !q.result.correct ? 'wrong mark-bad' : '')) : ''}}
```

### 3.4 「内容突然下推」跳变（体验缺口，已修）

**问题**：单选/迁移题反馈框是 `wx:if` 瞬时插入，插入瞬间把下方全部内容（继续按钮、提示坞）**一次性顶下去**。学习场景里最该看清的错因，恰好出现在一次视觉跳变之后。

**修法**：`mj-reveal` 同时动画 `max-height`（0 → 800rpx）+ `opacity` + `translateY`，让新增内容把下方**推开**而不是瞬移。
`overflow: hidden` 是让 `max-height` 动画能「裁剪出」渐进效果的必要条件；动画结束后 `max-height` 回 `auto`，内容再多也不会被裁掉。

> 这条不是「好看」，是「错因必须在视觉上可被读到」。因此在 `prefers-reduced-motion` 下**关闭动画但不隐藏内容**（见 §5）。

## 4. 音效与触觉接线（与音频线 UX-C 的接口）

本线负责「**在哪个手势里调用**」，音频线负责「**调用后怎么响**」。契约冻结在 `engine/audio.js`：`SFX_NAMES / init / sfx / startBgm / stopBgm / getPref / setPref`。

| 场景 | 音效 | 触觉 | 接线位置 |
|---|---|---|---|
| 引导页「开始体验」 | `tap` | `light` | `intro.js:84 onStart`（**全 App 首个手势**，音频线据此启动 BGM） |
| 普通点击 / 展开 | `tap` | `light` | `level.js tapFeedback()`、`map.js onTapLevel/onResume`、`review.js onToggle/onPractice` |
| 答对 | `correct` | `light` | `level.js judgeFeedback(true)` |
| 答错 | `wrong` | `medium` | `level.js judgeFeedback(false)` |
| 关卡结算 | `settle` | `medium` | `level.js finish()`、`result.js onLoad` |
| 金币收支 | `coin` | `light` | `level.js coinFeedback()`、`result.js onLoad`、`shop-settlement.js onSave` |
| 新解锁关卡 | `unlock` | — | `map.js refresh()` 差异检测 |
| 经营周结算 | `settle` | — | `shop-settlement.js refresh()`（`_settlePlayed` 保证只响一声） |

**落地计数**（`verify-ux-pass`）：`audio.sfx()` **14 处 / 7 个文件**（`tap` 7、`settle` 2、`coin` 2、`wrong`+`correct` 归入判定、`unlock` 1）；`wx.vibrateShort` **3 处**。

### 4.1 `map.js` 新解锁检测：为什么必须用会话变量而不是存档

```js
let knownUnlockedIds = null;   // 模块级，会话内有效
...
if (knownUnlockedIds && unlockedIds.some(id => knownUnlockedIds.indexOf(id) < 0)) {
  audio.sfx('unlock');
}
knownUnlockedIds = unlockedIds;
```

- **首帧只建基线、不发声**：`knownUnlockedIds === null` 时跳过，避免「冷启动进地图页」误报一串解锁音。
- **不写进 `state.js` 存档**：解锁音是**瞬时感知**，不是进度。写进存档会让「重装/换机后首次进入」误响，也会给存档结构增加一个纯展示字段（与既有「存档字段必须有人消费」的约束冲突）。
- 代价（已知）：同一会话内切出 App 再回来，`knownUnlockedIds` 仍在内存，行为正确；App 被杀掉重启则基线重置，不会补响历史解锁——这是可接受的。

### 4.2 手势栈风险（已知，已同步）

`result` / `shop-settlement` 的结算音、`map` 的解锁音触发在 `onLoad` / `onShow` 类**非手势**回调里。进入这些页面前用户必然已点击过（音频已解锁），多数平台允许「解锁后异步播放」；若真机无声，排查方向是挪到进入该页的那次点击上贴身触发，或接受静默。**音频失败不得影响任何页面展示**——所有调用点均 `try/catch` 静默降级。

### 4.3 音频开关入口（音频线实现，本线不写）

`pages/me/` 加两个 `<switch>`（背景音乐 / 音效），`onShow` 由 `getPref()` 回填；根节点 `bindtap="onPageTap"` 作**兜底手势入口**幂等启动 BGM（小程序无全局触摸监听 API，`play()` 必须在 `bindtap` 同步栈内）。
> 本线**未改** `me.wxml` / `me.js` 的开关部分；全站 setData 由 188 → 190 的 **+2 来自音频线这两个开关**，不是交互线。

## 5. 可访问性：动效不能成为信息唯一通道

`motion.wxss` §4 三条：

1. **形状冗余唯一来源是 `app.wxss` 的 `.mark-ok / .mark-bad / .mark-warn`**（美术线）。本文件曾另立 `.flag-right / .flag-wrong` —— **已删除**，调用点（`level.wxml` 两处 `.option`）统一改指 `.mark-*`。理由：形状冗余是**静态**可访问性属性，不属动效层；放基线才能在动效库被重构时依然存在。
2. **按钮按下态唯一来源是 `app.wxss`**。本文件曾重复声明一份并叠加 `opacity: 0.9` —— **已删除**（半透明与像素风的实色硬阴影语汇冲突，且两份定义互相覆盖）。
3. **`prefers-reduced-motion: reduce`** 关闭全部运动类动画，**只保留静态颜色/形状冗余**，信息不因关闭动画而丢失：
   ```css
   @media (prefers-reduced-motion: reduce) {
     .mj-pop, .mj-shake, .mj-reveal, .mj-dock, .mj-fade-up, .mj-star-pop, .mj-bar-grow,
     .mj-stagger .mj-stagger-item, .option.right, .option.wrong, .progress-fill, .l-fill,
     .points-fill, .decision-fill, .rating, .mj-stars .mj-star { animation: none !important; }
   }
   ```
   注意 `.mj-stars .mj-star` 必须显式列出（子选择器不随父类一起被 `animation: none` 覆盖）。
   另：`.mj-stagger` 内部直接子元素**必须**带 `.mj-stagger-item`，因为微信小程序 WXSS 编译器不支持 `.mj-stagger > *`。)

**填充/复述输入框的非颜色冗余**走「线型」通道（输入框是替换元素，无法用伪元素加字符）：

```css
.blank.ok, .rf-input.ok { border-style: double; border-width: 6rpx; }  /* 双线 = 正确 */
.blank.bad, .rf-input.bad { border-style: dashed; }                     /* 虚线 = 错误 */
```

## 6. 工程约束：为什么全部用 CSS class 驱动

`level.js` 是 1372 行的上帝文件，承载 **164 次 setData（占全站 190 次的 86%）**。任何用 JS 驱动动画的方案都会：

1. 继续推高渲染负担（每次 `setData` 都是一次跨线程通信）；
2. 引入时序不确定性（`setTimeout` 链与用户点击竞态，正是 §3.1 那个缺陷的同源问题）。

因此本线定死三条：

- **不用 `setTimeout + setData` 序列做动画**，全部由 CSS class 切换驱动。
- **单段动画（含 stagger 展开）总时长 ≤400ms**，且动画期间不阻塞任何下一步交互。
- **不使用全屏遮罩式庆祝**，不使用会导致元素位移进而误点的幅度（抖动 ≤8rpx）。

**结果验证**：`level.js` setData 164 → **164**（本线新增 0 次）。

## 7. 未做项与边界

- **未做页面转场动画**：小程序页面级转场由系统接管（`navigateTo` 无自定义转场 API），本线只做**页内**动效。
- **未做 `mj-shake` / `mj-star-pop` 独立工具类挂载**：两者已定义为公开工具类，但当前实际生效路径是 `.option.wrong`（shake）与 `.mj-stars .mj-star`（star-pop）。保留定义是为后续复用，**当前属未挂载工具类**，不构成死代码判定依据（动效库整体保留）。
- **未做音效/触觉的「开关」逻辑**：开关由音频线实现（§4.3），本线只负责调用点。
- **未做音量分级、震动强度自定义**：只提供音频双开关，不做滑杆。
- **未做 `level.js` 拆分**：`tests/structure-audit.test.js` 第 8 条用 `levelSrc.indexOf("case 'x'")` 断言，把「必须写在同一文件」固化成测试契约；拆分前必须先改那条断言。本线不碰。
- **未做「关卡加载骨架屏」**：无网络请求，无加载等待，无需求。
- **接 `shop-settlement` 的 `_settlePlayed` 实例标记**：页内 `onShow` 会重跑 `refresh`，用实例标记保证每次进入只响一声；代价是「同一实例内后退再进入」不重响，可接受。

### 8.1 必须由用户真机验证的清单

> 本环境无法实跑真机手势 / `InnerAudioContext` / 触觉。逐条「动作 → 期望」。

1. **答对动效**：单选答对 → 选项轻微上弹 + 逐行出现反馈框，**下方内容被渐进推开**（不是瞬移）。
2. **答错动效**：答错 → 选项横向抖动，幅度小到不会误触相邻选项。若抖动明显过大 → 检查 `mj-shake` 是否被页面样式覆盖。
3. **迁移题错项标记**：迁移题选错 → **用户所选选项本身**显示为错误态（含 ✗ 形状冗余 + 虚线边框），不再是「只有反馈框说错、选项无标记」。
4. **提示购买连点**：金币充足时**快速连点** L2「解锁」按钮 5 次 → 只应扣费一次、只解锁一次。若扣了多次 → 实例锁失效。
5. **星级逐个弹出**：通关结算 → 三颗星依次弹出（约 0/80/160ms 顺序），不是整串一起出现。
6. **进度条生长**：进关 / 答题推进 → 进度条从左向右生长，不是从中间向两边扩。若从中间扩 → `transform-origin` 未生效。
7. **提示坞展开**：点提示坞标题 → 内容淡入上滑展开，不是硬切换。
8. **减弱动态效果**：系统开启「减弱动态效果」→ 所有动画停止，但**颜色与形状标记仍然存在**，错因文字仍可见。若内容消失 → `mj-reveal` 的 `max-height` 需要在关闭动画时回 `auto`（检查 `animation: none !important` 是否连带把 `max-height` 锁死在 0）。
9. **触觉**：真机点击/判定 → 有轻振（答错中振）。开发者工具无触觉属正常，不得因无触觉弹任何提示或报错。
10. **性能体感**：连续快速答题 20 次，动效不卡顿、不丢帧；连点期间无「第二次点击丢失」（`guardSubmit` + 实例锁共同保证）。
11. **音效与动效协同**：答对时 `correct` 音与上弹动效应**同时**发生，不应有「先响后动」的时序错位。若错位明显 → 检查是否有页面在判定后追加了异步 setData。
